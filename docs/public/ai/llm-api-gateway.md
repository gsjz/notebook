从 26 年 4 月份到 8 月份，我用的 Codex API 中转站月租价涨了一倍。最开始我月租 ¥367.04 搞到日限额 $130 的中转站 API，用不完根本用不完；到现在月租 ¥328 只有日限额 $60 了，稍微修一修项目或者做做调研就花完了。有一说一，这个现在少有的月租中转站还是比较量大管饱，但还是少不了偶尔的抽风。还有一个问题是我有很多地方都需要用到 LLM API，如果以后不用这个中转站了，切换会很麻烦。于是我想到在自己的小服务器上自己搭建一个 API 个人聚合站，来保证更稳定统一的 Provider URL、更方便灵活的上游切换。

## 网络

### Tailscale

我的中转站域名 DNS 到 Tailscale 网段，两设备登录同一 Tailscale 账户即可实现虚拟局域网。这一块单独其实没太多好说的，但是它其实会间接引出两个 topic：一个是网络方面的（见 **【数据删除】** ）。一个是操作系统方面的（见 **守护进程** ），我们在后文讲述。

### 【数据删除】

其实如果你既需要【数据删除】，又想要用 Tailscale，那么它们的 DNS 很有可能发生冲突。如果你用的是类似【某软件】的软件，那么你应该对于你的域名做类似的 rule 设置

```
DOMAIN-SUFFIX,【你的域名后缀】,DIRECT
```

在设计时，我的个人聚合站顺便集成了【数据删除】的管理功能（见 **路由管理** ），我们在后文再讲述。

## 操作系统

### 守护进程

虽然我的小主机理想状况下是 24/7 工作的，但其实并不能简单假设它永远不可能关机重启。比如说有时我想重构走线布局、插拔一下电源，或者修其它电器的时候关电闸，它总还是要关机重启的。所以在 BIOS 层面，设置通电自动开机是一个方便的选择。具体的设置随具体 BIOS 版本而异。

还有一个问题是有时服务进程会挂掉。我希望它挂掉后，有一个东西会自动把它重新拉起来，这时候就可以用 Linux 的守护进程 Daemon 来实现。

## 应用设计

### 管理面板

其实对于上游的策略分配，还是【数据删除】的 rule，它们都是类似路由管理的功能。

### timeout 调参

似乎 codex 默认的本地 timeout 参数是 5 分钟（300 秒），超过这个时间它就尝试 reconnecting 了。

一个上游要是这么久不返回结果大概就是卡住了。假设我们使用一个月租 primary 上游和两个按量计费 backup 上游，那么可以考虑分别给他们分配 120 秒的 timeout。这个参数应该能保证一个相对均衡的性能和成本。
