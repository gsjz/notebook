# 网络分层模型

!!! abstract "本文要点"
    本文把网络分层模型压成一条容易背的主线：

    - 五层模型按“应用、传输、网络、链路、物理”理解真实通信过程。
    - 七层 OSI 模型是在五层的应用层附近多拆出“表示层、会话层”。
    - 每层用“通信范围、地址、数据单位、典型设备或协议”来定位。
    - 应试时重点区分协议、服务、接口，以及封装、PDU、端到端这些概念。

## 先记一句话

网络分层不要先背定义，先想象一次发消息：

```text
应用层：我要说什么
传输层：交给哪个进程
网络层：送到哪台主机
数据链路层：下一跳交给谁
物理层：比特怎么过线
```

!!! success "五层一口气背法"
    **应用写内容，传输找进程，网络找主机，链路找邻居，物理发比特。**

    从上到下背：`应用 -> 传输 -> 网络 -> 数据链路 -> 物理`。  
    从下到上背：`物理 -> 数据链路 -> 网络 -> 传输 -> 应用`。

这句话比单纯背层名更重要，因为考试通常不是问“第几层叫什么”，而是问某个功能、地址、设备、协议或数据单位属于哪一层。

## 为什么要分层

计算机网络太复杂，直接把所有功能写成一大块很难设计、维护和标准化。分层的做法是：每一层只解决一类问题，并向上一层提供服务。

!!! note "分层的核心"
    下层为上层提供服务，上层使用下层提供的服务；同一层的两个实体通过协议进行逻辑通信。

例如，HTTP 不需要自己研究路由怎么选，它把数据交给传输层；TCP 不需要自己控制每根网线上的电信号，它继续使用下面各层提供的能力。

分层带来的好处主要有：

- 每层功能相对独立，复杂问题被拆小。
- 层间接口清晰，一层内部实现变化时，不必大改所有上层。
- 不同厂商、不同系统可以按统一协议互通。
- 学习和排查问题时，可以按层定位。

!!! warning "不要误解分层"
    分层模型描述的是抽象功能和协议关系，不等于代码一定按这几层分别写成几个文件。体系结构关心“有哪些层、每层做什么、每层使用哪些协议”，不关心协议内部的具体实现细节。

## 五层模型

五层模型常用于学习计算机网络。它比 TCP/IP 四层模型更适合讲清底层差异，又比 OSI 七层模型更贴近实际互联网。

| 层次 | 解决的问题 | 典型数据单位 | 关键标识 | 常见协议或设备 |
| --- | --- | --- | --- | --- |
| 应用层 | 应用之间说什么格式的话 | 报文 | 域名、URL、应用语义 | HTTP、DNS、FTP、SMTP、SSH |
| 传输层 | 数据交给哪一个进程 | TCP 报文段 / UDP 数据报 | 端口号 | TCP、UDP |
| 网络层 | 数据送到哪一台主机 | IP 数据报 / 分组 | IP 地址 | IP、ICMP、路由器 |
| 数据链路层 | 在相邻节点间交付 | 帧 | MAC 地址 | 以太网、Wi-Fi、交换机、网卡 |
| 物理层 | 比特如何变成信号传输 | 比特流 | 无逻辑地址 | 中继器、集线器、接口电气特性 |

!!! tip "按通信范围记"
    - 数据链路层：**相邻节点到相邻节点**，看 MAC 地址。
    - 网络层：**主机到主机**，看 IP 地址。
    - 传输层：**进程到进程**，看端口号。
    - 应用层：**应用到应用**，看具体应用协议语义。

### 应用层

应用层直接面向网络应用，规定应用程序之间交换数据的格式和含义。

常见例子：

- 浏览网页：HTTP / HTTPS。
- 域名解析：DNS。
- 文件传输：FTP。
- 远程登录：SSH。
- 邮件发送：SMTP。

应用层不负责把比特送上网线，也不负责路由选择。它只关心“请求和响应长什么样”“字段是什么意思”“应用如何交互”。

### 传输层

传输层把主机上的多个应用进程区分开。IP 地址只能定位到主机或接口，端口号才能进一步定位到进程。

例如：

```text
203.0.113.10:443 -> Web 服务
203.0.113.10:22  -> SSH 服务
```

TCP 和 UDP 是传输层最常见的两个协议：

| 协议 | 特点 | 常见场景 |
| --- | --- | --- |
| TCP | 面向连接、可靠、有序、字节流 | HTTP/1.1、HTTP/2、SSH |
| UDP | 无连接、不保证可靠和有序、报文式 | DNS、DHCP、实时音视频、QUIC 的承载 |

!!! warning "端口号属于传输层"
    看到端口号、复用与分用、TCP 连接、UDP 数据报，优先想到传输层。

### 网络层

网络层解决跨网络转发问题：从源主机到目的主机，分组应该走哪条路。

它的核心标识是 IP 地址，核心动作是路由选择与分组转发。路由器通常工作到网络层，因此它根据目的 IP 地址和路由表决定下一跳。

!!! note "网络层不等于可靠送达"
    互联网中的 IP 提供的是无连接、尽最大努力交付服务。分组可能丢失、重复或失序；可靠性通常由传输层 TCP 或更高层机制补上。

### 数据链路层

数据链路层只负责一段链路上的相邻节点通信。它把网络层交来的 IP 数据报封装成帧，并在局域网或点到点链路上传输。

以以太网为例，帧里会出现源 MAC 地址和目的 MAC 地址。访问远端服务器时，目的 MAC 地址通常不是远端服务器的 MAC，而是本链路下一跳，例如默认网关的 MAC。

!!! tip "链路层关键词"
    看到帧、MAC 地址、以太网、交换机、网卡、差错检测、介质访问控制，优先想到数据链路层。

### 物理层

物理层负责把 0 和 1 表示成可传输的信号，并规定接口、电气特性、编码方式等低层细节。

它不关心 IP、端口、HTTP，也不理解帧里的字段含义。它只做最底层的比特传输。

!!! warning "传输介质不是协议层本身"
    双绞线、光纤、无线信道等传输介质和物理层关系很密切，但从分层模型看，介质本身通常不算物理层协议的组成部分。

## 七层 OSI 模型

OSI 七层模型自下而上是：

```text
物理层 -> 数据链路层 -> 网络层 -> 传输层 -> 会话层 -> 表示层 -> 应用层
```

从上往下看是：

```text
应用层 -> 表示层 -> 会话层 -> 传输层 -> 网络层 -> 数据链路层 -> 物理层
```

!!! success "七层速记"
    上三层可以记成：**应用要先表示清楚，再维持会话**。

    所以七层从上到下是：`应用 -> 表示 -> 会话 -> 传输 -> 网络 -> 数据链路 -> 物理`。

七层模型与五层模型最大的区别在上面三层：

| OSI 层次 | 主要功能 | 在五层模型中通常归入 |
| --- | --- | --- |
| 应用层 | 为具体网络应用提供服务入口 | 应用层 |
| 表示层 | 数据格式转换、编码、压缩、加密与解密 | 应用层 |
| 会话层 | 建立、管理、终止会话，提供同步点 | 应用层 |
| 传输层 | 进程到进程通信、复用分用、可靠传输等 | 传输层 |
| 网络层 | 路由选择、分组转发、网际互联 | 网络层 |
| 数据链路层 | 成帧、相邻节点交付、差错检测等 | 数据链路层 |
| 物理层 | 比特流传输、接口和信号特性 | 物理层 |

### 表示层怎么记

表示层解决“同一份数据在不同系统中怎么表示”的问题。

典型关键词：

- 字符编码转换。
- 数据格式转换。
- 数据压缩。
- 加密与解密。

!!! tip "表示层速记"
    表示层像“翻译和打包”：把数据翻译成对方能理解的表示形式，也可能顺手压缩或加密。

### 会话层怎么记

会话层管理一次会话的建立、维持和释放，并可提供同步点。

典型关键词：

- 会话建立、管理、终止。
- 对话控制。
- 同步点、检查点、断点恢复。

!!! tip "会话层速记"
    会话层像“对话管理”：谁先说、会话是否还在、断了能不能从检查点继续。

## 五层、七层、TCP/IP 四层的对应

真实互联网主要按 TCP/IP 协议族工作。学习时常见三套说法：

| 学习五层模型 | OSI 七层模型 | TCP/IP 四层模型 |
| --- | --- | --- |
| 应用层 | 应用层、表示层、会话层 | 应用层 |
| 传输层 | 传输层 | 传输层 |
| 网络层 | 网络层 | 网际层 |
| 数据链路层 | 数据链路层 | 网络接口层 |
| 物理层 | 物理层 | 网络接口层 |

!!! note "为什么常学五层"
    OSI 七层模型概念清楚，TCP/IP 四层模型贴近实际互联网。五层模型把 TCP/IP 的网络接口层拆成数据链路层和物理层，既方便理解，又不会在上层拆得太细。

## 封装与解封装

发送数据时，数据从应用层一路向下，每层加上自己的控制信息。接收数据时，数据从物理层一路向上，每层去掉对应控制信息。

```text
HTTP 报文
-> TCP 报文段
-> IP 数据报
-> 以太网帧
-> 比特流
```

接收端反过来：

```text
比特流
-> 以太网帧
-> IP 数据报
-> TCP 报文段
-> HTTP 报文
```

!!! note "PDU、SDU、PCI"
    - **PDU**：协议数据单元，对等层之间看到的数据单位。
    - **SDU**：服务数据单元，相邻层之间交付的数据。
    - **PCI**：协议控制信息，也就是本层加上的首部、尾部或控制字段。

公式可以记成：

$$
n\text{-SDU} + n\text{-PCI} = n\text{-PDU}
$$

也就是：上层交来的数据，加上本层控制信息，变成本层要传的 PDU。

## 一个访问网页的例子

浏览器访问 `https://www.example.com/`，可以按层理解：

| 层次 | 发生了什么 |
| --- | --- |
| 应用层 | DNS 查询域名，HTTP 构造请求，TLS/HTTPS 完成安全通信语义 |
| 传输层 | TCP 通过端口号连接到服务器的 `443` 端口 |
| 网络层 | IP 根据目的 IP 地址进行跨网络转发 |
| 数据链路层 | 每一跳都把 IP 数据报封装成当前链路的帧 |
| 物理层 | 把帧对应的比特变成电信号、光信号或无线信号 |

!!! warning "每一跳都可能换 MAC"
    端到端通信时，目的 IP 地址通常保持为最终服务器；但每经过一段链路，链路层帧的源 MAC 和目的 MAC 可能重新封装。IP 管“远方主机”，MAC 管“下一跳邻居”。

## 408 / 应试补充

### 高频判断题线索

| 题目关键词 | 优先对应层 |
| --- | --- |
| 比特、电气特性、接口机械特性、中继器、集线器 | 物理层 |
| 帧、MAC 地址、交换机、网桥、网卡、相邻节点、差错检测 | 数据链路层 |
| IP 地址、路由选择、分组转发、路由器、主机到主机 | 网络层 |
| 端口号、TCP、UDP、复用分用、端到端、进程到进程 | 传输层 |
| DNS、HTTP、FTP、SMTP、SSH、用户接口 | 应用层 |
| 格式转换、压缩、加密解密 | 表示层 |
| 会话管理、同步点、检查点、断点恢复 | 会话层 |

!!! tip "设备最高层"
    常见设备按最高工作层记：

    - 中继器、集线器：物理层。
    - 网桥、交换机：数据链路层。
    - 路由器：网络层。
    - 网关：可能工作到更高层，题目要看语境。

### 协议、服务、接口

这三个词经常一起考：

| 概念 | 方向 | 含义 |
| --- | --- | --- |
| 协议 | 水平 | 不同主机的对等层实体之间通信的规则 |
| 服务 | 垂直 | 下层通过接口向紧邻上层提供的功能 |
| 接口 | 垂直 | 同一主机内相邻两层之间使用服务的入口 |

!!! success "三词速记"
    **协议看左右，服务看上下，接口看入口。**

协议三要素也要一起记：

| 要素 | 解决的问题 | 例子 |
| --- | --- | --- |
| 语法 | 数据和控制信息格式 | TCP 首部字段格式 |
| 语义 | 字段含义、动作和应答 | SYN 表示请求建立连接 |
| 同步 / 时序 | 操作顺序和时间关系 | 三次握手、四次挥手的先后顺序 |

### 常见服务类型

| 分类角度 | 类型 | 记忆点 |
| --- | --- | --- |
| 是否先建立连接 | 面向连接 / 无连接 | TCP 面向连接；IP、UDP 常按无连接理解 |
| 是否保证交付 | 可靠 / 不可靠 | IP 尽最大努力交付，不保证可靠 |
| 是否自动确认 | 有应答 / 无应答 | 有应答会自动返回确认，应用也可自己实现确认 |

!!! warning "OSI 与 TCP/IP 的一个区别"
    OSI 参考模型中，网络层可支持无连接和面向连接服务，传输层只提供面向连接可靠服务；TCP/IP 体系中，网际层 IP 提供无连接不可靠服务，传输层同时有 TCP 和 UDP。

### 封装效率题

封装会带来额外控制信息，因此有效数据占比可以这样算：

$$
\text{传输效率}=\frac{\text{应用数据长度}}{\text{应用数据长度}+\text{各层额外开销总和}}
$$

例如，应用层要发送 `400B` 数据，若七层模型中除应用层和物理层外，中间 5 层每层增加 `20B` 开销，则：

$$
\text{传输效率}=\frac{400}{400+5 \times 20}=80\%
$$

!!! warning "物理层通常不做封装"
    封装题里，物理层的 PDU 是比特流，通常不再给数据加首部。题目若说“除物理层和应用层外”，就只数中间 5 层。

### 易混点速记

- **自下而上第一个端到端层**：传输层。
- **相邻节点流量控制**：数据链路层。
- **主机到主机通信**：网络层。
- **进程到进程通信**：传输层。
- **端口号**：传输层。
- **IP 地址**：网络层。
- **MAC 地址**：数据链路层。
- **会话层**：会话管理、同步点、检查点。
- **表示层**：格式转换、压缩、加密与解密。
- **体系结构**：层次、每层功能、每层协议；不包括协议内部实现细节。

!!! success "最后压缩成三行"
    五层：**应用内容，传输进程，网络主机，链路邻居，物理比特**。  
    七层：**应用、表示、会话** 是上三层，下面接 **传输、网络、链路、物理**。  
    做题：先找关键词，再定位 **单位、地址、设备、通信范围**。
