# 计算机网络常见算法与计算过程

## 计算模型与状态

网络计算题通常要求跟踪一个协议状态，再依据事件更新。先把“当前有哪些数据未确认”“下一跳是谁”“计时从哪个时刻开始”写清楚，公式才有确定含义。

| 过程 | 需要维护或计算的量 | 主要考查点 |
| --- | --- | --- |
| CRC | 多项式余数 | 补零、异或、校验位数与漏检边界 |
| 停止等待、GBN、SR | 序号、发送窗口、接收窗口、计时器 | 确认语义、回绕、重传范围与利用率 |
| CSMA/CD | 传播时延、碰撞次数、退避随机数 | 最短帧长与截断指数退避 |
| 最长前缀匹配 | 目的地址与转发表 | 掩码匹配及最长前缀选择 |
| 距离向量、链路状态 | 距离向量或拓扑数据库 | 路由更新与最短路径计算 |
| BGP | 属性、策略与下一跳可达性 | 按给定优先级逐项筛选 |
| TCP 拥塞控制 | 拥塞窗口、接收窗口、在途数据 | 慢开始、拥塞避免、丢失后的状态变化 |

本页的帧长、数据量与窗口单位会在相应公式前定义。链路速率中的 $\mathrm{Mb/s}$ 通常按十进制计量，$1\,\mathrm{B}=8\,\mathrm{bit}$；TCP 窗口若按 MSS 计数，应先换成字节再与接收窗口比较。

## CRC 与模二除法

CRC 把比特串视为二元域上的多项式。设数据为 $M(x)$，生成多项式为 $G(x)$，次数为 $r$。发送方计算：

$$
R(x)=x^rM(x)\bmod G(x),\qquad
C(x)=x^rM(x)+R(x).
$$

运算中的加减均为异或，无进位、无借位。这样构造的发送串 $C(x)$ 能被 $G(x)$ 整除，附加的 $r$ 位余数称为 FCS。余数不足 $r$ 位时要在左侧补零。

发送方先在数据后补 $r$ 个零，然后从最左侧的一开始对齐生成多项式，异或消去该位，重复到余式次数低于 $r$。接收方直接检查完整接收串，不再补零。

!!! question "例题：CRC 校验位"
    数据为 `101001`，生成多项式对应比特串 `1101`。求 FCS、发送串，并说明接收方余数为零意味着什么。

    ??? success "参考答案"
        生成多项式为 $x^3+x^2+1$，故附加 $3$ 位校验。补零和异或过程为：

        ```text
        101001000
        011101000
        000111000
        000001100
        000000001
        ```

        FCS 为 `001`，发送串为 `101001001`。接收方用 `1101` 除完整发送串，余数为 `000`。

        余数为零表示未检测到差错。若差错多项式恰好是生成多项式的倍数，也会漏检；CRC 本身不提供重传、纠错或抵抗主动篡改的认证能力。

下面保留与手算一致的实现，输入应是非空的二进制字符串，生成多项式首尾为一、长度至少为二，且被除串不短于生成多项式。实际以太网 CRC 还规定初值、反射和最终异或等参数，不能直接把这个教学实现当成 Ethernet FCS 实现。

```cpp title="教学用模二除法"
std::string remainder(std::string bits, const std::string& generator) {
    for (std::size_t i = 0; i + generator.size() <= bits.size(); ++i) {
        if (bits[i] == '0') continue;
        for (std::size_t j = 0; j < generator.size(); ++j) {
            bits[i + j] = (bits[i + j] == generator[j]) ? '0' : '1';
        }
    }
    return bits.substr(bits.size() - (generator.size() - 1));
}

std::string encode(const std::string& data, const std::string& generator) {
    const auto r = generator.size() - 1;
    return data + remainder(data + std::string(r, '0'), generator);
}

bool check(const std::string& received, const std::string& generator) {
    const auto rem = remainder(received, generator);
    return rem.find('1') == std::string::npos;
}
```

## 滑动窗口与可靠传输

发送窗口限制允许发送但尚未确认的数据，接收窗口限定当前可接受的序号范围。连续发送把等待确认的时间用于发送后续帧；序号、确认与计时器用于识别重复并恢复丢失。

设发送窗口大小为 $W_T$，接收窗口大小为 $W_R$。它们是协议许可范围，不等于设备全部物理缓存容量。停止等待的设备即使拥有很大内存，协议仍只允许一个未确认帧在途。

| 协议 | 发送窗口 | 接收窗口 | 确认与出错处理 |
| --- | --- | --- | --- |
| 停止等待 | $1$ | $1$ | 确认或超时后决定是否发送下一个帧 |
| GBN，后退 N 帧 | 可大于 $1$ | $1$ | 累积确认；失序帧不缓存，超时回退重传 |
| SR，选择重传 | 可大于 $1$ | 可大于 $1$ | 逐帧确认并缓存窗口内失序帧，只重传相应帧 |

本节统一约定：**GBN 的 ACK 携带下一个期望序号**，例如 ACK 2 累积确认序号 2 之前的帧；**SR 的 ACK 直接确认指定帧**。有些题目把 GBN ACK 编号定义成最后一个正确接收帧的序号，计算前应先转换，不能在一道题中混用两种约定。

### GBN 的窗口更新

发送方维护最早未确认帧 `base` 和下一个待发送帧 `next`，可发送范围为从 `base` 起的 $W_T$ 个序号。收到新的累积确认才移动窗口；仅发送完成不会释放窗口位置。

接收方只交付当前期望帧。后续帧先到时，即使无差错也丢弃，并返回当前期望序号。典型 GBN 对最早未确认帧维护计时器，超时后重传所有已发但未确认的帧。

```text
初始发送窗口：{0, 1, 2, 3}
已发送：      {0, 1, 2}
收到 ACK 2：  0、1 已确认
新的发送窗口：{2, 3, 4, 5}
```

以下伪代码使用**本地绝对编号**展示状态，省略序号回绕、计时器实现和缓存操作。线路上只发送模序号，实际实现必须将确认映射到当前有效范围，不能直接使用普通整数大小比较。

```text
send_available():
    while 有数据 and next < base + WT:
        保存并发送帧 next
        if base == next: 启动最早未确认帧计时器
        next = next + 1

on_ack(k):                    # k 是展开后的“下一个期望编号”
    if base < k <= next:
        释放 [base, k) 的副本
        base = k
        if base == next: 停止计时器
        else: 重启计时器
        send_available()

on_timeout():
    重传 [base, next) 内所有帧
    重启计时器
```

### SR 的缓存与重复确认

SR 收到接收窗口内的正确帧就缓存并单独确认。只有从窗口左端开始已经连续收到的部分，才能按序交付上层并推动接收窗口。

如果一个旧帧已被接收、但对应 ACK 丢失，发送方会再次发送它。接收方对**刚刚越过窗口的已接收旧帧**应再次确认，不能只因它已不在当前窗口就完全忽略。否则发送方可能一直等待这个 ACK，无法推动窗口。

```text
on_receive(frame):
    if 校验失败: 丢弃
    else if 序号属于当前接收窗口:
        缓存该帧（已有副本则不重复存储）
        发送该序号的 ACK
        while 窗口左端帧已经收到:
            向上交付并前移窗口
    else if 序号属于协议可识别的上一接收窗口:
        再次发送该序号的 ACK
    else:
        丢弃

on_individual_ack(k):
    若 k 对应当前发送窗口中已发送的帧，标记确认并停止其计时器
    仅当窗口左端连续确认后，才释放副本并前移窗口

on_timeout(k):
    仅重传尚未确认的帧 k，并重启对应计时器
```

“上一窗口”必须依据模序号规则识别，不能无限期保存一个数值就认定它永远属于旧数据。协议还隐含帧寿命、链路排序或序号复用方面的条件；有限序号不能识别跨越任意多个回绕周期仍未消失的古老副本。

### 序号空间与回绕

若序号字段为 $n$ 位，共有 $M=2^n$ 个序号，按模 $M$ 循环。判断序号 $s$ 是否在从 $b$ 开始、长度为 $W$ 的窗口内，可以使用：

$$
(s-b)\bmod M<W.
$$

例如模 $8$、窗口左端为 $6$、长度为 $4$，窗口为 $\{6,7,0,1\}$。普通条件 $6\le s<10$ 无法正确判断线路序号零和一。

在标准教材滑动窗口模型下：

$$
\begin{aligned}
\text{GBN: }&W_T\le2^n-1,\quad W_R=1,\\
\text{SR: }&W_T+W_R\le2^n.
\end{aligned}
$$

SR 常取对称窗口 $W_T=W_R\le2^{n-1}$。这些约束防止仍可能重传的旧序号与可接收的新序号重叠。GBN 的发送窗口为一时退化为停止等待；教材强调连续发送时常写 $1<W_T$。

!!! question "例题：SR 的旧帧歧义"
    序号只有两位，发送与接收窗口都取 $3$。发送方发出序号 0、1、2，接收方均收到并交付，但三个 ACK 全丢失。说明窗口设置有什么问题，并与窗口取 $2$ 时比较。

    ??? success "参考答案"
        序号空间为 $4$，两个窗口之和为 $6>4$。接收方交付 0、1、2 后，当前窗口变成 $\{3,0,1\}$；发送方超时重传的旧帧 0 会落入当前窗口，被误认为下一轮的新帧。

        窗口取 $2$ 时，收到并交付 0、1 后当前窗口为 $\{2,3\}$，重传的 0、1 可识别为上一窗口的旧帧。接收方再次确认即可，不重复交付。

### 利用率与带宽时延积

设链路速率为 $C$，每帧线路长度为 $L$ 比特，发送时延为 $T_D=L/C$；单向传播时延为 $\tau$，ACK 发送时延为 $T_A$。假定无差错、无排队、处理可忽略、接收方收完立即确认，正反向传输互不争用。

从第一帧开始发送，到完整 ACK 返回，经过：

$$
T_{\mathrm{cycle}}=T_D+2\tau+T_A.
$$

停止等待与连续发送窗口为 $W_T$ 的利用率分别为：

$$
U_{\mathrm{SW}}=\frac{T_D}{T_D+2\tau+T_A},\qquad
U=\min\left(1,\frac{W_TT_D}{T_D+2\tau+T_A}\right).
$$

若题目用 RTT 表示往返传播时间，则可把 $2\tau$ 换成 RTT。若给的是从发送开始到 ACK 返回的整个测量周期，就不能再加一次数据发送时间。实际网络 RTT 还可能包含处理、排队和 ACK 策略的影响。

保持发送端持续忙碌所需的最小窗口为：

$$
W_{\min}=\left\lceil\frac{T_D+2\tau+T_A}{T_D}\right\rceil.
$$

带宽时延积 $C\cdot\mathrm{RTT}$ 反映保持在途所需的数据量级。若只计应用有效数据，设每帧有效载荷为 $L_P$ 比特，则理想 goodput 为 $UC(L_P/L)$，不能将包含首部和重传的链路吞吐量直接视为应用速率。

!!! question "例题：目标利用率与序号位数"
    链路速率为 $2\,\mathrm{Mb/s}$，数据帧总长 $1000\,\mathrm{B}$，单向传播时延 $10\,\mathrm{ms}$。忽略 ACK 发送、处理和排队，无差错。若目标利用率至少为 $80\%$，GBN 需要的最小发送窗口与序号位数是多少？相同窗口的对称 SR 又需要几位？

    ??? success "参考答案"
        $T_D=8000/(2\times10^6)=4\,\mathrm{ms}$，一个确认周期为 $4+20=24\,\mathrm{ms}$。

        由 $4W_T/24\ge0.8$ 得 $W_T\ge4.8$，故最小整数窗口为 $5$。GBN 要求 $2^n-1\ge5$，至少 $3$ 位。对称 SR 要求 $2W_T\le2^n$，窗口为 $5$ 时至少 $4$ 位。若要满利用率，窗口至少为 $6$。

## CSMA/CD 与截断二进制指数退避

CSMA/CD 适用于共享介质、半双工以太网。发送前监听，发送中检测碰撞，发生碰撞后停止数据发送并发出干扰信号，随后随机退避。现代交换式全双工以太网不存在同样的共享介质碰撞，不执行这套竞争机制；Wi-Fi 使用的 CSMA/CA 也不能直接套用此处的碰撞检测公式。

设最大单向传播时延为 $\tau$。最远两端可能在尚未听见对方信号时先后开始发送，最迟接近 $2\tau$ 后，先发送者才能发现碰撞。要保证发现时仍在发送，应满足：

$$
\frac{L_{\min}}{C}\ge2\tau,
\qquad L_{\min}\ge2\tau C.
$$

题目若包含中继器等设备时延，应把它们计入规定的往返碰撞检测时间。实际标准还规定时隙长度等参数，不能只用实际电缆长度任意缩短以太网最短帧。

在经典 $10\,\mathrm{Mb/s}$ 模型中，时隙为 $51.2\,\mathrm{\mu s}$，对应 $512$ 比特，即 $64\,\mathrm{B}$ 的最短 MAC 帧。它包括 MAC 首部和 FCS，不包括前导码和帧间间隔。

第 $i$ 次碰撞后的退避窗口取：

$$
k=\min(i,10),\quad r\in\{0,1,\ldots,2^k-1\},\quad
T_{\mathrm{backoff}}=rT_{\mathrm{slot}}.
$$

$r$ 按均匀分布随机选取，零表示不额外退避，仍须满足介质访问条件。截断的是指数增长的范围，超过十次后不再扩大。经典以太网在同一帧的发送尝试达到碰撞上限时放弃，通常描述为第十六次碰撞；教材可能按“重传次数”计数，解题前应检查是否把初次发送计入。

!!! question "例题：退避时间的上界与均值"
    某帧第三次碰撞后，时隙为 $51.2\,\mathrm{\mu s}$。求额外随机退避时间的最大值和期望值。

    ??? success "参考答案"
        $k=3$，$r$ 从 $0$ 至 $7$ 等概率选择。最大退避时间为 $7\times51.2=358.4\,\mathrm{\mu s}$；期望为 $\frac{0+7}{2}\times51.2=179.2\,\mathrm{\mu s}$。这只包括随机退避，不包括等待其他站点占用信道的时间。

## 最长前缀匹配

普通目的地址路由先找出所有匹配项，再选择前缀最长的一项。设目的地址为 $D$，规范化前缀为 $P$，对应掩码为 $M$，匹配条件为：

$$
D\mathbin{\&}M=P.
$$

```text
best = 无匹配
for entry in 转发表:
    if (目的地址 AND entry.mask) == entry.prefix:
        if best 为空 or entry.prefix_length > best.prefix_length:
            best = entry
```

`/32` 主机路由比任何匹配的更短前缀具体，`/0` 默认路由的优先级最低。若最长前缀仍有多个等价下一跳，可能采用 ECMP 等机制；路由协议优先级、度量等通常先用于产生可安装路由，不应把这些条件与不同长度前缀的匹配顺序混用。

!!! question "例题：重叠前缀的下一跳"
    转发表如下，分别确定目的地址 `192.0.2.200` 和 `192.0.2.140` 的下一跳。

    | 前缀 | 下一跳 |
    | --- | --- |
    | `0.0.0.0/0` | R1 |
    | `192.0.2.0/24` | R2 |
    | `192.0.2.128/25` | R3 |
    | `192.0.2.192/26` | R4 |

    ??? success "参考答案"
        `192.0.2.200` 同时匹配四项，选择 `/26`，下一跳为 R4。

        `192.0.2.140` 位于 `/25` 的范围内，但不在 `/26` 的 `192.0.2.192` 至 `192.0.2.255` 内，故选择 R3。不能看到一个更长前缀就直接选择，必须先验证匹配。

取得下一跳后，路由器仍须解析相应链路地址。下一跳 IP 通常不替换原分组的目的 IP，只有特定 NAT、隧道等功能会按其规则改写或增加地址。

## 路由计算：距离向量与链路状态

路由计算产生可达性与下一跳信息，转发查表处理实际分组。前者在控制平面运行，后者依赖其已安装结果；控制信息尚未收敛时，分组可能遇到暂时环路或黑洞。

### 距离向量与 RIP 更新

设节点 $x$ 到邻居 $v$ 的链路代价为 $c(x,v)$，邻居报告到目的 $y$ 的距离为 $d_v(y)$，Bellman–Ford 更新为：

$$
d_x(y)=\min_{v\in N(x)}\{c(x,v)+d_v(y)\}.
$$

节点只需要邻居距离及本地链路代价，无需先掌握完整拓扑。RIP 采用跳数度量，可达距离最大为 $15$，$16$ 表示不可达；距离不等于传播时延或可用带宽。

处理来自邻居 $v$ 的 RIP 表项时，把通告距离加一并截断到 $16$，下一跳候选为 $v$。新目的加入表；不同下一跳的候选更短时采用；**当前路由本就经过 $v$ 时，要更新该邻居的最新距离，即使距离增大**。只允许“取更小值”会把失效路径永久留在表中。

!!! question "例题：来自当前下一跳的坏消息"
    路由器 X 当前到网络 N 的距离为 $3$、下一跳为 A，到网络 P 的距离为 $5$、下一跳为 B。X 收到直接邻居 A 的通告：到 N 的距离为 $7$，到 P 的距离为 $2$。按教材 RIP 单次更新规则得到什么结果？

    ??? success "参考答案"
        经过 A 的候选距离分别为 $8$ 和 $3$。N 原来就经 A 到达，应更新为距离 $8$、下一跳 A；P 的候选 $3$ 小于原来的 $5$，更新为距离 $3$、下一跳 A。

        如果实现还保存其他邻居的可用候选，可重新比较选出更好的路由；题目只给这一份更新时，不应凭空添加备用路径。

距离向量可能因过时消息产生无穷计数。水平分割、毒性逆转、触发更新与超时可缓解收敛问题，但不能由此推断任何拓扑和故障下都瞬时无环。

### 链路状态与 Dijkstra

链路状态协议洪泛本地邻接与代价信息，使同一区域中的路由器获得拓扑数据库，再各自运行最短路径算法。OSPF 有区域层次，并非每台路由器都必须保存整个自治系统的全部链路细节。

Dijkstra 要求边权非负。每一步选出未确定节点中暂定距离最小者，将它的距离确定，再松弛其邻居。更新距离时还应保存前驱或首跳，才能构造转发表。

!!! question "例题：最短路径的确定顺序"
    无向图包含边 A—B，代价 $2$；A—C，代价 $5$；B—C，代价 $1$；B—D，代价 $4$；C—D，代价 $1$。从 A 运行 Dijkstra，给出距离更新及到 D 的下一跳。

    ??? success "参考答案"
        | 已确定节点 | 到 B 的暂定距离 | 到 C 的暂定距离 | 到 D 的暂定距离 |
        | --- | ---: | ---: | ---: |
        | A | $2$ | $5$ | $\infty$ |
        | A、B | $2$ | $3$ | $6$ |
        | A、B、C | $2$ | $3$ | $4$ |
        | A、B、C、D | $2$ | $3$ | $4$ |

        最短路径为 A—B—C—D，总代价 $4$，A 的下一跳为 B。最短路径树优化源点到各点的路径长度，与最小生成树的“全树边权总和最小”目标不同。

| 比较项 | 距离向量 | 链路状态 |
| --- | --- | --- |
| 交换内容 | 到各目的的距离信息 | 本地邻接与代价信息 |
| 传播方式 | 主要与直接邻居交换 | 在规定作用域内洪泛 |
| 本地计算 | Bellman–Ford 式更新 | 基于拓扑运行 Dijkstra |
| 典型协议 | RIP | OSPF |
| 主要边界 | 过时邻居信息、无穷计数 | 数据库同步、洪泛与重计算开销 |

链路状态也可能在故障收敛期间出现短暂转发环路，不能把“每个节点独立算最短路”理解为动态过程始终一致。

### BGP 的策略筛选

BGP 用于自治系统之间的路由交换，并通过 AS_PATH 等属性携带路径信息。目的在于满足策略并维持可达性，AS 路径更短不必意味着时延更低。

教材常给出“本地偏好更高 → AS_PATH 更短 → 内部到出口的代价更小 → 标识符破同分”的简化顺序。仅在题目限定其他属性相同、候选可用时，才按此顺序计算。真实实现还涉及可达性、ORIGIN、MED、eBGP/iBGP 等条件，细节受标准、配置和厂商实现影响。

BGP 的 NEXT_HOP 可能不是当前路由器直接相邻的节点，需要由 IGP 或其他路由递归解析为实际转发下一跳。“热土豆”比较的是离开本 AS 的内部代价，不能把它替换成端到端时延最小。

| 协议 | 常见承载 | 路由作用 |
| --- | --- | --- |
| RIP | UDP `520`，此处指 IPv4 RIPv2 | 距离向量、AS 内路由 |
| OSPF | 直接承载于 IP，协议号 `89` | 链路状态、AS 内路由 |
| BGP | TCP `179` | 策略路由、AS 间及 AS 内 BGP 信息传播 |

“负责网络层路由”与“自身报文封装在哪一层”是不同问题。路由协议使用 TCP 或 UDP 承载，不会把所计算的 IP 路由变成应用数据转发规则。

## TCP 窗口与拥塞控制

### 接收能力、网络负载与可发送量

接收窗口 $\mathrm{rwnd}$ 约束接收端可接收的数据范围，拥塞窗口 $\mathrm{cwnd}$ 约束发送端对网络的在途数据估计。若均按字节计量，常见简化上限为：

$$
W=\min(\mathrm{rwnd},\mathrm{cwnd}).
$$

它表示允许的在途量上限，不是此刻还能立刻发送的全部数据。设尚未确认的在途数据量为 $F$，忽略 SACK、恢复期等更复杂约束时，新数据可发送量至多为：

$$
\max(0,W-F).
$$

例如接收窗口为 $12000\,\mathrm{B}$，拥塞窗口为 $10$ MSS，MSS 为 $1000\,\mathrm{B}$，已有 $7000\,\mathrm{B}$ 未确认，则理想情况下还可发送 $3000\,\mathrm{B}$。流量控制面向接收端，拥塞控制面向网络负载，二者不能相互替代。

### 教材中的按轮次模型

画曲线前必须声明初始窗口、门限、ACK 假设与算法版本。常见题设以一个 RTT 为一轮，以 MSS 为窗口单位，假定数据充足、接收窗口不构成限制、每个新段被及时确认、起始窗口为一。

令窗口为 $w$，慢开始门限为 $s$。一种常见离散化约定是：

$$
w_{t+1}=\begin{cases}
\min(2w_t,s),&w_t<s,\\
w_t+1,&w_t\ge s.
\end{cases}
$$

这描述教材的整轮近似。慢开始实质由新数据确认驱动，在上述理想条件下约每 RTT 翻倍；拥塞避免约每 RTT 增加一个 MSS。门限相等时的阶段选择，以及跨越门限的一轮如何计数，应按题干约定。

发生超时时，教材常取 $s\leftarrow\max(w/2,2)$、$w\leftarrow1$，重新慢开始。三次重复 ACK 触发快重传；若题目采用省略恢复期细节的模型，则把下一阶段窗口设为新的门限并进入拥塞避免。

!!! question "例题：门限与超时后的轮次"
    使用上述教材离散模型，初始 $w_1=1$，$s=6$。写出前六轮开始时的窗口。第六轮发送后发生超时，按第六轮窗口的一半设置新门限，求第七至第十轮的窗口。

    ??? success "参考答案"
        前六轮依次为 $1,2,4,6,7,8$。第三轮后到门限即停止指数增长，因此第四轮为 $6$。

        超时后门限为 $4$，第七轮窗口重置为 $1$。第七至第十轮依次为 $1,2,4,5$。这里每个数都指该轮开始时的窗口，不能把轮末更新后的数值提前一轮标注。

### Reno 的恢复过程与实际标准

教材中“快恢复后减半”省略了恢复阶段。RFC 5681 的经典 Reno 基线使用实际未确认的数据量 FlightSize 计算新的门限，不能无条件拿理论拥塞窗口替代。按字节计量，常用更新为：

$$
\mathrm{ssthresh}=\max\left(\frac{\mathrm{FlightSize}}2,2\,\mathrm{SMSS}\right),
$$

其中 SMSS 为发送方最大报文段数据长度。标准要求门限不大于相应计算值，具体实现还可更保守。

| 事件 | 经典 Reno 的主要动作 |
| --- | --- |
| 第三个重复 ACK | 重传丢失段，设置门限，令 $\mathrm{cwnd}=\mathrm{ssthresh}+3\,\mathrm{SMSS}$ 进入快恢复 |
| 更多重复 ACK | 按协议条件临时增加窗口，表示后续数据已离开网络 |
| 恢复阶段的相应新确认 | 将窗口收缩到门限，退出快恢复 |
| 重传超时 | 大幅收缩窗口，经典基线至一个满尺寸段，重新慢开始 |

NewReno 和 SACK 对部分确认、多段丢失有不同恢复规则。三次重复 ACK 是丢失推断信号，也可能由重排序触发；现代实现还采用更细的丢失检测机制。因此，不宜用一段只含“重复 ACK 后直接减半”的伪代码声称实现了完整 TCP。

### 高带宽路径与现代拥塞控制

初始拥塞窗口一 MSS 是常见题设，不能当成现代系统的固定默认值。RFC 6928 给出了更大的初始窗口建议，通常概括为上限约十个 MSS，实际取值还受字节上限与实现影响。

CUBIC 使用与距上次拥塞事件的时间相关的三次函数调节窗口，适用于高带宽、较长 RTT 等场景，并保留与 Reno 友好的工作区域。它不会逐 RTT 完全复现教材的线性曲线。ECN 还允许网络通过标记反馈拥塞，不必等到丢包后才调整。

当带宽时延积较大时，窗口过小会限制吞吐；窗口足够大以后，继续增加窗口也可能只增加队列和时延。优化下载速度应同时观察吞吐、RTT、丢包、接收窗口和应用处理能力，不能仅追求更大的缓冲区。
