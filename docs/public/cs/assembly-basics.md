# 汇编语言基础

汇编语言用助记符、寄存器名和地址表达式描述机器指令。理解一段汇编，需要同时确定指令集体系结构（ISA）、汇编语法和调用约定：ISA 规定指令效果，语法决定操作数怎样书写，调用约定决定参数、返回值和寄存器保存责任。相同 ISA 上也可以存在不同调用约定。

本文代码采用 **x86-64、Intel 语法**，操作数顺序为目标在前、源在后。涉及函数参数时采用 System V AMD64 ABI；寻址方式公式则使用组成原理中的抽象机器模型。

## 指令集与执行状态

ISA 规定指令格式、数据类型、寻址方式、体系结构寄存器和异常等可见行为。流水线级数、物理寄存器数量、执行单元数量、控制器采用硬布线还是微程序，属于实现选择。

| 状态或部件 | 阅读代码时关注的内容 |
| --- | --- |
| 通用寄存器 | 当前值、操作数位宽、值被当作整数还是地址 |
| 程序计数器 | 顺序地址、分支目标，以及相对位移采用的基准 |
| 栈指针 | 栈顶位置、每次调整的字节数、调用前后的平衡 |
| 条件码 | 哪条指令最后更新了它，跳转使用哪些标志 |
| 内存 | 有效地址、访问字节数、字节序、读写方向 |

教学取指模型常在取指后将 `PC` 更新为下一条顺序指令地址；具体 ISA 对可见 PC、分支基准和异常保存地址有独立规定。例如 x86 相对转移以**本条指令结束后的地址**为基准，RISC-V 的条件分支以**分支指令本身的地址**为基准，不能互相套用。

`IR`、`MAR`、`MDR` 分别描述内部指令暂存、访存地址暂存和访存数据暂存，通常不能作为普通汇编操作数。`PC` 可由控制转移间接改变，但“程序员可见”也不意味着所有 ISA 都允许把它当通用寄存器任意读写。

### 寄存器位宽与内存宽度

x86-64 中 `rax` 是 $64$ 位寄存器，`eax` 是其低 $32$ 位。写入 `eax` 会把 `rax` 的高 $32$ 位清零；写入 `ax`、`al` 通常只修改对应的低位部分。这个规则经常影响指针和整数转换题。

```asm title="数据传送与访问宽度"
mov eax, 42           ; rax = 42，高 32 位清零
mov ebx, eax          ; 复制 32 位值
mov ecx, [rbp-4]      ; 从地址 rbp-4 读取 4 字节
mov [rbp-8], eax      ; 向地址 rbp-8 写入 4 字节
mov rdx, [rbx]        ; 从 rbx 指向的位置读取 8 字节
lea rdx, [rbx+rcx*4]  ; 计算地址，不读取该地址中的内存
```

内存访问宽度可以由寄存器操作数推断；无法推断时须显式注明，如 `mov DWORD PTR [rbx], 1`。`lea` 的方括号表示地址表达式，不能一看到方括号就认定发生了访存。

x86 使用小端序：多字节整数的低有效字节放在低地址。字节序影响多字节值与内存字节的对应关系，不改变一个字节内部的位编号，也不改变寄存器中整数的数学含义。

## 算术、标志位与条件跳转

固定宽度整数运算首先产生截断后的位模式。对 $n$ 位加法，保存的结果是数学和模 $2^n$；有符号与无符号解释共用这些结果位，但越界判断不同。

| x86 标志 | 含义 |
| --- | --- |
| `CF` | 加法的最高位进位；减法中的无符号借位 |
| `OF` | 有符号结果超出所用位宽的补码范围 |
| `ZF` | 截断后的结果是否为零 |
| `SF` | 截断后结果的最高位 |

常见运算指令包括 `add` / `sub` 加减、`inc` / `dec` 加减一、`and` / `or` / `xor` / `not` 位逻辑，以及 `shl` / `shr` 移位。`shr` 为逻辑右移，高位补零；有符号算术右移使用 `sar`，高位复制符号位，不能对负数直接互换。

`cmp a, b` 按减法计算标志，但不保存差值。随后选择哪组跳转条件，取决于题目要求的数值解释。

| 关系 | 无符号跳转 | 有符号跳转 |
| --- | --- | --- |
| 相等 | `je`：$ZF=1$ | 同左 |
| 不等 | `jne`：$ZF=0$ | 同左 |
| 小于 | `jb`：$CF=1$ | `jl`：$SF\ne OF$ |
| 大于等于 | `jae`：$CF=0$ | `jge`：$SF=OF$ |
| 大于 | `ja`：$CF=0\land ZF=0$ | `jg`：$ZF=0\land SF=OF$ |
| 小于等于 | `jbe`：$CF=1\lor ZF=1$ | `jle`：$ZF=1\lor SF\ne OF$ |

常见指令的标志位副作用不能一概而论：`add`、`sub` 更新算术标志；`inc`、`dec` 保留 `CF`；`mov`、`lea`、`not` 不改算术标志；移位的标志定义还依赖移位次数。因此分析跳转前要追溯**最近一次实际写入所用标志的指令**。这些规则属于 x86；RISC-V 基础整数分支直接比较寄存器，没有同一套条件码寄存器。

!!! question "例题：同一位模式的两种比较"
    执行 `mov eax, -1`、`cmp eax, 1` 后，`ja` 与 `jg` 哪一个会跳转？`rax` 的完整值是多少？

    ??? success "参考答案"
        `eax` 的位模式为 $\mathtt{FFFFFFFF}$，按无符号数解释为 $2^{32}-1$，大于 $1$，所以 `ja` 跳转；按 $32$ 位补码解释为 $-1$，所以 `jg` 不跳转。

        写 `eax` 清零高半部，故 `rax` 为 $\mathtt{00000000FFFFFFFF}$，并非 $64$ 位的 $-1$。`cmp` 不修改 `eax` 或 `rax`。

## 寻址方式与有效地址

令 $A$ 为指令中的地址或位移字段，$R_i$ 为寄存器内容，$M[x]$ 为地址 $x$ 处的内存内容，$EA$ 为有效地址。下表的访存次数只计**读取操作数**，不计取指、不计结果写回，并假设指针与操作数各一次即可读出。

| 方式 | 操作数或有效地址 | 额外读内存次数 |
| --- | --- | --- |
| 立即寻址 | 操作数为 $A$ | $0$ |
| 寄存器寻址 | 操作数为 $R_i$ | $0$ |
| 直接寻址 | $EA=A$，操作数为 $M[EA]$ | $1$ |
| 存储器间接寻址 | $EA=M[A]$，操作数为 $M[EA]$ | $2$ |
| 寄存器间接寻址 | $EA=R_i$ | $1$ |
| 相对寻址 | $EA=P_{\mathrm{base}}+\operatorname{sext}(A)$ | 用于转移时不据此读取数据操作数 |
| 基址寻址 | $EA=R_{\mathrm{base}}+A$ | 通常为 $1$ |
| 变址寻址 | $EA=A+R_{\mathrm{index}}$ | 通常为 $1$ |
| 堆栈寻址 | 栈顶位置由 `SP` 隐含指定 | 随指令确定 |

基址寻址在教材中侧重程序定位，变址寻址侧重数组索引；现代 ISA 常把基址、比例变址和位移合进同一个表达式。x86 的常见形式为：

$$
EA=R_{\mathrm{base}}+sR_{\mathrm{index}}+d,\qquad s\in\{1,2,4,8\}
$$

这里算出的通常是进程地址空间中的地址。页表和 TLB 负责后续地址转换；有效地址不宜直接等同于 DRAM 的物理位置。

!!! question "例题：数组地址与加载结果"
    `rbx` 保存数组首地址 $\mathtt{1000H}$，`rcx` 的值为 $3$，每个元素占 $4\,\mathrm{B}$。执行 `mov eax, [rbx+rcx*4+8]` 时，有效地址是多少？若该处连续四字节为 `78 56 34 12`，结果是什么？

    ??? success "参考答案"
        $EA=\mathtt{1000H}+3\times4+8=\mathtt{1014H}$，对应从零编号的第 $5$ 个元素。小端解释得到 $\mathtt{12345678H}$，写入 `eax` 后 `rax` 的高 $32$ 位为零。

!!! question "例题：相对分支的地址基准"
    某 x86 指令起始地址为 $\mathtt{1000H}$，长度为 $5\,\mathrm{B}$，相对位移为 $-12\,\mathrm{B}$。转移目标是多少？

    ??? success "参考答案"
        先得到下一条地址 $\mathtt{1005H}$，再加有符号位移：$\mathtt{1005H}-\mathtt{CH}=\mathtt{0FF9H}$。若换成另一 ISA，须重新确认位移基准、单位及缩放规则。

## 分支、循环与调用

读机器级代码时，可按基本块划分控制流：块内顺序执行，块末由条件转移、无条件转移或返回决定后继。跟踪表至少记录循环变量、累计结果、循环条件和退出值；内存写入及栈变化单独记录。

### 累加循环

下面保留一个直接的循环实现。输入为 `edi` 中的有符号整数 $n$，返回值位于 `eax`。限定 $0\le n\le65535$，保证下面 C 代码的有符号累加不溢出，也保证循环变量不会回绕。

```asm title="sum_to_n.asm"
mov eax, 0
mov ecx, 1
.Lloop:
cmp ecx, edi
jg .Ldone
add eax, ecx
inc ecx
jmp .Lloop
.Ldone:
ret
```

```c title="对应的 C 语义"
int sum_to_n(int n) {
    int sum = 0;
    int i = 1;
    while (i <= n) {
        sum += i;
        i++;
    }
    return sum;
}
```

循环头的不变式为：当 `ecx` 为 $i$ 时，`eax` 保存 $1+\cdots+(i-1)$。比较后若 $i>n$ 就退出，否则累加当前项并递增。用这个不变式可以核对初始化、边界和返回值，无需机械翻译每一行。

!!! question "例题：循环执行次数"
    上述代码输入 $n=3$ 时，`cmp`、`add` 和 `inc` 各执行几次？退出时 `eax`、`ecx` 分别是多少？

    ??? success "参考答案"
        循环体执行 $3$ 次，故 `add`、`inc` 各 $3$ 次。退出判断额外执行一次，`cmp` 共 $4$ 次。最终 `eax` 为 $6$，`ecx` 为 $4$。输入 $n=0$ 时仍执行一次比较，循环体执行零次。

### 返回地址、栈与 ABI

x86-64 的普通近调用 `call` 把返回地址压栈，再转移到目标；`ret` 从栈取回返回地址。`jmp` 不执行这项返回地址保存。其他 ISA 可以把返回地址放入链接寄存器，例如 RISC-V 的 `jal`，嵌套调用时再按 ABI 保存。

System V AMD64 ABI 用 `rdi`、`rsi`、`rdx`、`rcx`、`r8`、`r9` 依次传递前六个整数或指针参数，常用 `rax` 返回结果；`rbx`、`rbp`、`r12` 至 `r15` 属于被调用者保存寄存器。参数传递和保存责任是 ABI 约定，不能仅凭 `call` 指令推导。

栈题应按指令顺序记录 `rsp`：普通 $64$ 位 `push` 和近 `call` 使其减少 $8$，`pop` 和普通近 `ret` 使其增加 $8$。局部变量还可能由 `sub rsp, ...` 分配；栈向低地址增长并不意味着数组下标也向低地址增长。

## 机器级语义与现代实现

乱序处理器可以让无依赖指令提前执行，但要维持 ISA 允许的软件可见结果。寄存器重命名解决假相关，不能消除真正的数据依赖；误预测路径上的指令最终不能作为正常结果提交。性能分析因此还要考察依赖链、执行端口、缓存命中和分支预测，汇编指令条数本身不足以决定耗时。

将 C 翻译为汇编时还应区分语言语义：无符号整数回绕有明确定义，C 的有符号溢出通常属于未定义行为。不能用 x86 加法的截断行为替代 C 对溢出的规定。
