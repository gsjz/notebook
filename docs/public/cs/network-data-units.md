# 各层典型数据单位

!!! abstract "本文要点"
    本文把网络分层中的典型数据单位放在同一条封装链上理解：

    - 五层模型中，各层常见数据单位分别是什么。
    - 报文、报文段、数据报、分组、帧、比特流之间有什么关系。
    - 为什么同一个词在不同语境下可能有不同含义。
    - 408 做题时如何快速定位层次、地址和转发范围。

## 先看一条封装链

从发送端看，应用数据会一层一层向下交付。每层通常会给上层数据加上本层控制信息，形成本层的数据单位。

```text
应用层报文
-> TCP 报文段 / UDP 用户数据报
-> IP 数据报 / 分组
-> 数据链路层帧
-> 物理层比特流
```

接收端则反过来：

```text
比特流
-> 帧
-> IP 数据报 / 分组
-> TCP 报文段 / UDP 用户数据报
-> 应用层报文
```

!!! success "一句话总览"
    **应用层说报文，传输层说 TCP 报文段或 UDP 数据报，网络层说 IP 数据报或分组，链路层说帧，物理层说比特流。**

这里的名字不是孤立背诵的。更重要的是理解：上一层的数据会成为下一层的数据部分，下一层再加自己的首部或尾部。

## PDU、SDU 与 PCI

!!! note "三个通用名词"
    - **PDU**：Protocol Data Unit，协议数据单元，是某一层对等实体之间看到的数据单位。
    - **SDU**：Service Data Unit，服务数据单元，是上层交给本层的数据。
    - **PCI**：Protocol Control Information，协议控制信息，是本层加入的首部、尾部或控制字段。

三者关系可以写成：

$$
n\text{-PDU}=n\text{-SDU}+n\text{-PCI}
$$

如果第 $n+1$ 层把自己的 PDU 交给第 $n$ 层使用，那么它在第 $n$ 层看来就是 $n$-SDU。

```text
HTTP 报文       是应用层 PDU
HTTP 报文       交给 TCP 后，成为 TCP 的 SDU
TCP 加首部后    形成 TCP 报文段，也就是传输层 PDU
TCP 报文段      交给 IP 后，成为 IP 的 SDU
IP 加首部后     形成 IP 数据报，也就是网络层 PDU
```

!!! tip "核心理解"
    **PDU 是从本层对等通信角度看的名字；SDU 是从相邻层接口角度看的名字。**同一段比特，在不同视角下可能有不同称呼。

## 五层典型数据单位

| 层次 | 典型数据单位 | 本层主要控制信息 | 主要通信范围 |
| --- | --- | --- | --- |
| 应用层 | 报文 | 应用协议字段，如请求行、查询内容、命令等 | 应用到应用 |
| 传输层 | TCP 报文段 / UDP 用户数据报 | 端口号、序号、确认号、检验和等 | 进程到进程 |
| 网络层 | IP 数据报 / 分组 | IP 地址、TTL、分片字段、协议字段等 | 主机到主机 |
| 数据链路层 | 帧 | MAC 地址、类型字段、帧定界、FCS 等 | 相邻节点到相邻节点 |
| 物理层 | 比特流 | 信号、编码、接口特性等 | 逐链路传输比特 |

!!! warning "不要只背单位"
    数据单位要和 **地址、范围、设备** 一起记：端口号对应传输层，IP 地址对应网络层，MAC 地址对应数据链路层；路由器按 IP 转发分组，交换机按 MAC 转发帧。

## 各层单位分别解决什么问题

### 应用层报文

应用层报文描述应用程序之间要交换的具体语义。不同应用协议的报文格式不同，例如 HTTP 请求、HTTP 响应、DNS 查询、SMTP 命令等。

```text
GET /index.html HTTP/1.1
Host: example.com
```

这是 HTTP 报文的一部分。它表达的是“请求哪个资源、使用什么协议版本、访问哪个主机名”等应用语义。

!!! note "应用层的重点"
    应用层不负责路由选择，也不负责把数据放到网线上。它规定的是应用之间如何组织和解释数据。

### 传输层报文段与用户数据报

传输层要把数据交给正确的应用进程，所以它最关键的标识是端口号。

| 协议 | 常见数据单位 | 特点 |
| --- | --- | --- |
| TCP | 报文段 | 面向连接、可靠、有序、面向字节流 |
| UDP | 用户数据报，也常简称 UDP 数据报 | 无连接、不保证可靠和有序、面向报文 |

TCP 把应用交来的字节流切成合适大小的报文段。每个 TCP 报文段有序号、确认号、窗口等字段，用于可靠传输、流量控制和拥塞控制。

UDP 则保留应用报文边界。应用交给 UDP 一个报文，UDP 加上 8B 首部后形成一个 UDP 用户数据报，再交给 IP 层。

!!! warning "TCP 与 UDP 的单位差异"
    TCP 常说 **报文段**，因为它面向字节流，可以按 MSS 切分数据。UDP 常说 **用户数据报**，因为它面向报文，一次交付一个完整报文，不主动拆分或合并应用报文。

### 网络层 IP 数据报与分组

网络层负责把数据从源主机送向目的主机。互联网中的 IP 提供无连接、尽最大努力交付服务，典型数据单位是 IP 数据报。

在很多教材和题目中，网络层单位也常叫 **分组**。分组强调“分组交换中被存储转发的小数据块”，IP 数据报则强调它是 IP 协议的数据单位。

!!! note "IP 数据报与分组"
    在 408 网络层语境中，**IP 数据报通常可以看作一种具体的分组**。如果题目泛谈分组交换、路由器转发、网络层服务，常用“分组”；如果题目谈 IPv4 首部、TTL、片偏移、协议字段，常用“IP 数据报”。

路由器收到一帧后，会剥掉链路层首部和尾部，取出其中的 IP 数据报，再根据目的 IP 地址查转发表，决定下一跳。

### 数据链路层帧

数据链路层负责一段链路上的相邻节点交付。它把网络层交来的 IP 数据报封装成帧，并在本链路上传输。

以以太网为例，帧中有源 MAC 地址、目的 MAC 地址、类型字段和 FCS。目的 MAC 地址通常表示本链路的下一跳，而不一定是最终目的主机。

!!! warning "帧是逐跳变化的"
    跨网络传输时，IP 数据报的源 IP 和目的 IP 通常保持端到端不变；但每经过一段链路，链路层帧都会重新封装，源 MAC 和目的 MAC 可能变化。

### 物理层比特流

物理层处理的是 0 和 1 如何通过电信号、光信号或无线信号传输。它不理解 IP 地址、端口号、HTTP 字段，也不按“报文”或“帧字段”解释数据语义。

!!! tip "物理层记法"
    看到比特、信号、电气特性、机械特性、编码、调制、中继器、集线器，优先想到物理层。

## 关系示例：一次 DNS 查询

假设主机要查询 `www.example.com` 的 IP 地址，常见封装关系如下：

```text
DNS 查询报文
-> UDP 用户数据报
-> IP 数据报
-> 以太网帧
-> 比特流
```

| 层次 | 数据单位 | 关键字段 |
| --- | --- | --- |
| 应用层 | DNS 报文 | 查询名、查询类型 |
| 传输层 | UDP 用户数据报 | 源端口、目的端口 `53`、长度、检验和 |
| 网络层 | IP 数据报 | 源 IP、目的 IP、协议字段 UDP |
| 数据链路层 | 以太网帧 | 源 MAC、目的 MAC、类型字段 IP |
| 物理层 | 比特流 | 编码后的 0/1 信号 |

如果 DNS 服务器不在本局域网，数据链路层帧的目的 MAC 通常是默认网关的 MAC，而 IP 数据报的目的 IP 仍是 DNS 服务器的 IP。

!!! success "抓包阅读顺序"
    抓到一个以太网帧时，通常按外到内读：先看帧首部，再看 IP 首部，再看 TCP/UDP 首部，最后看应用层数据。

## 关系示例：一个 HTTP 请求

浏览器访问网页时，HTTP 请求通常封装在 TCP 中：

```text
HTTP 请求报文
-> TCP 报文段
-> IP 数据报
-> 以太网帧
-> 比特流
```

TCP 是字节流协议。应用层写入的一段 HTTP 请求，在传输层可能被放进一个 TCP 报文段，也可能因为大小、MSS、拥塞窗口等因素被分成多个 TCP 报文段。

!!! warning "应用报文不一定等于一个 TCP 报文段"
    TCP 不保留应用报文边界。一个 HTTP 报文可能跨多个 TCP 报文段，一个 TCP 报文段中也可能承载应用层连续写入的多段数据。做题时若没有特别说明，不要把“一个应用报文”和“一个 TCP 报文段”机械等同。

## 几个容易混的名字

### 报文

“报文”是一个较宽泛的词，常见含义有三种：

- 应用层协议报文，例如 HTTP 报文、DNS 报文、SMTP 报文。
- 报文交换中的整个报文，即未切成分组的大数据单位。
- 某些协议控制报文，例如 ICMP 报文、路由协议报文。

!!! tip "看修饰语"
    看到“报文”不要立即定层，要看前面的协议名和题目语境：HTTP 报文在应用层，ICMP 报文与 IP 网络层关系密切，TCP 报文段在传输层。

### 数据报

“数据报”也有层次差异：

| 名称 | 所在层次 | 含义 |
| --- | --- | --- |
| IP 数据报 | 网络层 | IP 协议的数据单位 |
| UDP 用户数据报 | 传输层 | UDP 协议的数据单位 |
| 数据报服务 | 网络层服务方式 | 无连接、每个分组独立转发 |

!!! warning "IP 数据报和 UDP 数据报不是一层"
    IP 数据报由路由器在网络层处理和转发；UDP 用户数据报是 IP 数据报的数据部分，路由器正常转发时不会按 UDP 首部做普通路由决策。

### 分组、包、帧

分组通常用于网络层和分组交换语境，强调被存储转发的小单位；包是口语化说法，可能泛指 packet；帧则是数据链路层的严格术语。

```text
IP 数据报封装在帧中：

[以太网首部 | IP 首部 | TCP/UDP 首部 | 应用数据 | FCS]
```

!!! warning "帧不等于分组"
    帧用于一段链路内传输，含 MAC 地址和 FCS；分组用于网络层转发，含 IP 地址。路由器转发时会去掉输入链路的帧封装，再为输出链路重新封装新的帧。

## MTU、MSS 与各层单位大小

数据单位不仅名字不同，大小限制也可能来自不同层。

| 名词 | 所在层次 | 含义 |
| --- | --- | --- |
| MTU | 数据链路层影响网络层 | 一帧数据部分可承载的最大网络层数据长度 |
| IP 分片 | 网络层 | IP 数据报超过下一段链路 MTU 时可能被切成多个片 |
| MSS | 传输层 TCP | TCP 报文段中应用数据部分的最大长度 |

以常见以太网 `MTU = 1500B` 为例，若 IPv4 首部 `20B`、TCP 首部 `20B`，则为了避免 IP 分片，TCP 常选择：

$$
\text{MSS}=1500-20-20=1460\text{B}
$$

!!! tip "大小关系"
    MTU 限制的是链路层帧的数据部分；MSS 限制的是 TCP 报文段的数据部分。MSS 通常要扣掉 IP 首部和 TCP 首部，目标是让整个 IP 数据报能放进一帧的数据部分。

## 408 / 应试补充

### 高频对应表

| 关键词 | 优先对应 |
| --- | --- |
| HTTP、DNS、FTP、SMTP、请求、响应、命令 | 应用层报文 |
| 端口号、复用分用、TCP 序号、确认号、窗口 | 传输层报文段 / 用户数据报 |
| IP 地址、TTL、路由表、分片、片偏移、尽最大努力交付 | 网络层 IP 数据报 / 分组 |
| MAC 地址、帧定界、FCS、交换机、网桥、网卡 | 数据链路层帧 |
| 比特、信号、编码、接口特性、中继器、集线器 | 物理层比特流 |

### 常见判断

- 应用层的典型数据单位是报文。
- TCP 的典型数据单位是报文段，UDP 的典型数据单位是用户数据报。
- 网络层的典型数据单位可称为分组，IP 协议下常称 IP 数据报。
- 数据链路层的典型数据单位是帧。
- 物理层的典型数据单位是比特流。
- IP 地址定位主机或接口，端口号定位主机中的应用进程，MAC 地址定位一段链路上的相邻节点。
- 路由器转发 IP 分组时要处理物理层、数据链路层和网络层，但通常不处理应用层报文语义。
- 交换机转发帧时主要看 MAC 地址，不看 IP 地址做三层路由选择。

### 易混点速记

!!! warning "最容易错的四组"
    - **IP 数据报 vs UDP 数据报**：前者是网络层，后者是传输层。
    - **分组 vs 帧**：分组看 IP 地址跨网络转发，帧看 MAC 地址逐链路交付。
    - **TCP 报文段 vs 应用报文**：TCP 面向字节流，不保证一个应用报文对应一个 TCP 段。
    - **端到端 vs 逐跳**：传输层是进程到进程的端到端逻辑通信；数据链路层是相邻节点之间的逐跳交付。

### 做题步骤

1. 先看题目给的协议名：HTTP、DNS、TCP、UDP、IP、以太网分别能快速定位层次。
2. 再看地址字段：端口号定位传输层，IP 地址定位网络层，MAC 地址定位数据链路层。
3. 接着看设备：集线器在物理层，交换机在数据链路层，路由器在网络层。
4. 最后看通信范围：进程到进程是传输层，主机到主机是网络层，相邻节点是数据链路层。

!!! success "最后压缩"
    封装关系记成：**报文进段，段进数据报，数据报进帧，帧变比特流**。  
    定位层次记成：**端口找进程，IP 找主机，MAC 找邻居**。
