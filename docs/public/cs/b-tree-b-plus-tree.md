# B 树与 B+ 树

## 多路搜索树的动机

普通二叉搜索树、AVL 树和红黑树都属于二叉结构。它们在内存中很好用，因为一次指针跳转的代价相对较小。

但数据库索引、文件系统索引这类结构通常存放在磁盘或 SSD 上。外存访问的主要成本不是比较几个关键字，而是读写数据页。

如果一棵树很高，每访问一层就可能触发一次页面读取，那么即使每层查找很快，整体 I/O 成本也会很高。

B 树和 B+ 树的核心思想是：让一个结点尽量对应一个磁盘页，在一个结点里放多个关键字和多个孩子指针，从而把树的高度压得很低。

!!! note "外存索引的核心矛盾"
    在数据库场景中，关键问题通常不是“比较一次关键字要多久”，而是“为了找到目标记录要读多少个页”。B 树和 B+ 树通过提高分支因子减少树高，本质上是在减少随机 I/O 次数。

## B 树的定义

B 树是一种多路平衡搜索树。不同教材会用“阶”或“最小度数”描述它，记号略有差异。这里先用 $m$ 阶 B 树说明。

一棵 $m$ 阶 B 树通常满足：

1. 每个结点最多有 $m$ 棵子树，最多有 $m-1$ 个关键字。
2. 除根结点外，非叶结点至少有 $\lceil m/2\rceil$ 棵子树，至少有 $\lceil m/2\rceil-1$ 个关键字。
3. 若根结点不是叶结点，则根至少有 2 棵子树。
4. 每个结点内关键字有序。
5. 有 $k$ 个关键字的非叶结点有 $k+1$ 棵子树。
6. 所有叶结点都在同一层。

对于一个结点：

```text
[K1 | K2 | K3]
 /    |    |    \
P0   P1   P2   P3
```

关键字范围满足：

- `P0` 中所有关键字小于 `K1`。
- `P1` 中所有关键字位于 `K1` 与 `K2` 之间。
- `P2` 中所有关键字位于 `K2` 与 `K3` 之间。
- `P3` 中所有关键字大于 `K3`。

!!! warning "阶的定义要看教材"
    有些资料用 $m$ 表示最多孩子数，有些资料用最小度数 $t$ 表示每个结点的关键字范围为 $t-1$ 到 $2t-1$。做题时先确认题目采用哪套定义，再套上下界。

## B 树的查找

B 树查找从根结点开始。

1. 在当前结点内部查找关键字。
2. 如果命中，查找成功。
3. 如果未命中，根据关键字区间选择对应孩子指针。
4. 重复直到叶结点。

因为结点内部关键字有序，可以顺序查找，也可以二分查找。实际系统中，一个结点通常对应一个页，页内比较在内存完成，页与页之间的跳转才是外存访问重点。

!!! tip "B 树查找的代价模型"
    分析 B 树时可以把代价拆成两层：树高决定页面访问次数，结点内关键字数决定页内比较次数。数据库索引更关心前者。

!!! note "复杂度记号约定"
    下面用 $n$ 表示整棵树中的关键字数，$m$ 表示 B 树的阶或最大孩子数，$h$ 表示树高。由于 B 树保持平衡，通常有 $h=O(\log_m n)$。

    如果把 $m$ 当作外部给定的常数，查找、插入、删除都可以简写成 $O(\log n)$。如果像算法竞赛题那样把结点内关键字移动也算进复杂度，就要保留每层的 $O(m)$ 或 $O(\log m)$ 因子。

!!! tip "查找复杂度"
    按步骤看，查找每下降一层会读入一个结点，并在该结点内定位关键字或孩子区间。

    - 页内顺序查找：每层 $O(m)$，总时间 $O(hm)$。
    - 页内二分查找：每层 $O(\log m)$，总时间 $O(h\log m)$。
    - 外存 I/O：最多访问从根到叶的一条路径，为 $O(h)$ 次页面访问。
    - 额外空间：迭代实现为 $O(1)$，递归实现为 $O(h)$ 调用栈。

## B 树的插入与分裂

B 树插入时，总是在叶结点插入新关键字。插入后如果结点关键字数超过上限，就要分裂。

分裂的基本动作是：

1. 把溢出结点按中间关键字分成左右两个结点。
2. 中间关键字上移到父结点。
3. 父结点接收新的孩子指针。
4. 如果父结点也溢出，继续向上分裂。

如果根结点分裂，就会生成新的根，树高增加 1。

```text
插入后溢出：
[10 | 20 | 30 | 40 | 50]

中间关键字上移：
        [30]
       /    \
[10 | 20]  [40 | 50]
```

!!! tip "插入复杂度"
    插入可以拆成“定位叶子、页内插入、向上分裂”三段。

    - 定位叶子：与查找相同，顺序页内查找为 $O(hm)$，二分页内查找为 $O(h\log m)$。
    - 叶子内插入：为了保持关键字有序，最坏需要移动 $O(m)$ 个关键字。
    - 分裂调整：一次分裂需要重排当前结点的关键字和孩子指针，代价 $O(m)$；最坏一路分裂到根，总代价 $O(hm)$。
    - 总时间：竞赛式写法通常记为 $O(hm)$；若 $m$ 视为常数，则为 $O(\log n)$。
    - 额外空间：迭代维护父指针时为 $O(1)$，递归实现为 $O(h)$；结构增长时最坏会新增 $O(h)$ 个结点，但这属于数据结构本身的存储增长。

## B 树的删除与合并

B 树删除时要保持每个结点关键字数不低于下限。

常见处理思路是：

- 如果删除的是叶结点关键字，直接删除后检查是否低于下限。
- 如果删除的是内部结点关键字，通常用前驱或后继关键字替换，再转化为删除叶结点中的关键字。
- 如果某结点关键字不足，优先向相邻兄弟借关键字。
- 如果兄弟也不能借，就与兄弟合并，并把父结点中的分隔关键字下移。

删除可能导致父结点继续不足，因此调整可能向上递归。若根结点变空，树高会减少 1。

!!! tip "删除复杂度"
    删除的难点不在找到关键字，而在保持每个结点不低于下限。

    - 定位待删关键字：与查找相同，顺序页内查找为 $O(hm)$，二分页内查找为 $O(h\log m)$。
    - 内部结点替换：寻找前驱或后继只沿一条路径向下走，仍是 $O(hm)$ 或 $O(h\log m)$。
    - 借关键字或合并：单层调整需要移动关键字和孩子指针，代价 $O(m)$；最坏向上连锁调整 $h$ 层，总代价 $O(hm)$。
    - 总时间：通常记为 $O(hm)$，当 $m$ 为常数时为 $O(\log n)$。
    - 额外空间：迭代实现为 $O(1)$，递归实现为 $O(h)$。

## B+ 树与 B 树的区别

B+ 树是数据库索引中更常见的变体。它和 B 树的最大区别是：数据记录或记录指针只放在叶子层，内部结点只保存用于导航的关键字和孩子指针。

| 对比项 | B 树 | B+ 树 |
| --- | --- | --- |
| 数据位置 | 关键字和数据可出现在内部结点或叶结点 | 数据或记录指针只在叶结点 |
| 内部结点作用 | 同时可能命中数据和导航 | 只做导航 |
| 叶子层 | 不一定需要链起来 | 通常按关键字顺序链起来 |
| 等值查找 | 可能在内部结点结束 | 通常都查到叶结点 |
| 范围查询 | 可能需要中序遍历多个分支 | 沿叶子链顺序扫描更方便 |

!!! note "B+ 树为什么适合数据库"
    B+ 树内部结点不存放完整数据记录，因此同样大小的页能容纳更多关键字和孩子指针，分支因子更大，树高更低。同时，叶子结点有序相连，范围查询和排序扫描更自然。

## 数据库中的 B+ 树场景

数据库表通常很大，无法把全部记录长期放在内存中。数据库管理系统会把表数据和索引切成固定大小的页，例如 4KB、8KB 或 16KB。B+ 树的一个结点通常就设计成一个或若干个页。

一次通过索引查找记录，可以粗略理解为：

1. 从根页开始，根据查询关键字选择下一层页。
2. 读入内部索引页，在页内比较关键字。
3. 一层层走到叶子页。
4. 在叶子页找到目标键对应的记录、记录指针或主键值。
5. 如果索引页没有包含所需全部列，再回到数据页读取完整记录。

!!! example "等值查询"
    对 `where id = 42` 这类等值条件，如果 `id` 上有 B+ 树索引，数据库可以从根页一路定位到包含 `42` 的叶子页，而不是从表的第一页开始全表扫描。

!!! tip "B+ 树等值查询复杂度"
    B+ 树等值查询通常不会在内部结点结束，而是一路走到叶子层。

    - 内部页导航：访问 $h$ 层，每层页内定位孩子区间。
    - CPU 时间：顺序页内查找为 $O(hm)$，二分页内查找为 $O(h\log m)$。
    - 外存 I/O：索引页访问为 $O(h)$；若不是覆盖索引，还可能额外回表访问数据页。
    - 额外空间：只保存当前页和少量状态，通常为 $O(1)$。

### 范围查询

B+ 树特别适合范围查询，例如：

```sql
select *
from orders
where created_at >= '2026-01-01'
  and created_at <  '2026-02-01';
```

执行时可以先定位到第一个满足条件的叶子项，然后沿叶子结点链表顺序向后扫描，直到超过范围上界。

这比在一棵普通二叉树上反复查找每个值更适合外存，因为连续叶子页更容易被预读，也更符合范围扫描的访问模式。

!!! tip "范围查询复杂度"
    设范围内实际返回 $r$ 条记录，每个叶子页平均能容纳 $b$ 个叶子项。

    - 定位起点：先做一次下界查找，时间 $O(h\log m)$ 或 $O(hm)$，I/O 为 $O(h)$。
    - 顺序扫描：沿叶子链扫描输出结果，CPU 时间至少要 $O(r)$。
    - 总时间：常写为 $O(h\log m+r)$，若页内顺序查找则为 $O(hm+r)$。
    - 外存 I/O：约为 $O(h+\lceil r/b\rceil)$ 个页面，实际还受预读、缓存和回表影响。
    - 额外空间：流式输出为 $O(1)$；如果把结果全部收集到数组中，则输出空间为 $O(r)$。

### 聚簇索引与辅助索引

数据库实现各有差异，但可以抓住一个通用模型：

- 聚簇索引：叶子层直接存放完整数据记录，数据本身按索引键的顺序组织。
- 辅助索引：叶子层通常存放索引键和记录定位信息，例如主键值或物理行地址。
- 覆盖索引：如果查询所需列都能从某个辅助索引叶子项中得到，就不必再访问数据页。

!!! warning "不要把 B+ 树叶子项想得过于固定"
    不同数据库、不同存储引擎的叶子项内容不完全相同。理解时重点看它保存的是“完整记录”还是“找到记录所需的定位信息”，不要把某个具体系统的实现当成所有数据库的统一规则。

### 组合索引与最左前缀

组合索引可以理解为按多个列拼成一个复合关键字，例如：

```sql
create index idx_user_time on login_log(user_id, login_time);
```

B+ 树会先按 `user_id` 排序；当 `user_id` 相同时，再按 `login_time` 排序。

因此，这个索引适合：

- `where user_id = ?`
- `where user_id = ? and login_time >= ?`
- `where user_id between ? and ?`

但通常不适合单独高效支持：

- `where login_time >= ?`

因为在整棵树上，`login_time` 并不是第一排序关键字，单独按它查找无法形成连续的全局区间。

!!! tip "最左前缀的直觉"
    组合索引像按字典顺序排序的电话簿。先按姓排，再按名排。如果不知道姓，只按名找人，就很难直接定位到一个连续区间。

!!! tip "组合索引复杂度"
    组合索引能否高效，关键看查询条件能不能形成从最左列开始的连续有序区间。

    - 满足最左前缀：先定位区间下界，再顺序扫描匹配项，复杂度类似 $O(h\log m+r)$。
    - 只缺少后缀条件：仍可用前缀定位，例如 `user_id = ?` 可以走索引。
    - 缺少最左列：通常无法直接定位连续区间，最坏退化为扫描大量索引项，可近似看作 $O(n)$。
    - 空间复杂度：查询过程本身通常为 $O(1)$，输出结果另计 $O(r)$。

## B+ 树与红黑树的适用场景

红黑树适合内存中的有序集合或映射，因为它每个结点只保存少量信息，指针跳转多，但内存随机访问代价较低。

数据库索引更关心页 I/O。假设一个内部索引页能放 200 个分支，那么树高为 3 时，理论上就能覆盖约：

$$
200^3 = 8{,}000{,}000
$$

个叶子方向。实际容量还会受到页大小、键长度、填充率和记录指针大小影响，但“高扇出带来低树高”这个结论不变。

| 结构 | 适合场景 | 原因 |
| --- | --- | --- |
| 红黑树 | 内存有序表、语言库映射结构 | 指针操作灵活，更新维护成本较低 |
| B+ 树 | 数据库索引、文件系统索引 | 结点按页组织，分支因子大，范围扫描友好 |
| 哈希索引 | 精确等值查询 | 平均等值查找快，但不天然支持有序范围扫描 |

!!! note "数据库索引的常见结论"
    B+ 树不是因为比较次数最少而流行，而是因为它把索引组织成高度很低、页访问友好、范围扫描友好的结构。

## 考试补充

B 树和 B+ 树的题目常围绕“阶、关键字数、孩子数、树高、插入分裂、删除合并”展开。

常用关系要记清：

- $m$ 阶 B 树中，一个结点最多有 $m$ 个孩子，最多有 $m-1$ 个关键字。
- 有 $k$ 个关键字的非叶结点通常有 $k+1$ 个孩子。
- 除根以外，结点关键字数不能低于下限。
- 所有叶结点在同一层，这是 B 树平衡性的核心。
- B+ 树的叶子层保存全部关键字，并通常顺序链接。

!!! warning "常见易错点"
    B 树和 B+ 树都不是二叉树。B+ 树内部结点中的关键字主要用于导航，不代表完整记录一定存放在那里。范围查询要优先想到 B+ 树叶子链，而不是从根反复查找每个关键字。

!!! tip "数据库题的答题关键词"
    看到数据库索引，优先写“页”“磁盘 I/O”“高扇出”“低树高”“叶子链表”“范围查询”。这些词比单纯说 $O(\log n)$ 更贴近数据库场景。

### 复杂度速记

| 操作 | CPU 时间 | 外存 I/O | 额外空间 |
| --- | --- | --- | --- |
| B 树查找 | $O(h\log m)$ 或 $O(hm)$ | $O(h)$ | $O(1)$ 迭代，$O(h)$ 递归 |
| B 树插入 | $O(hm)$ | $O(h)$ 到 $O(h)$ 级写回 | $O(1)$ 迭代，结构增长另计 |
| B 树删除 | $O(hm)$ | $O(h)$ 到 $O(h)$ 级写回 | $O(1)$ 迭代，$O(h)$ 递归 |
| B+ 树等值查询 | $O(h\log m)$ 或 $O(hm)$ | $O(h)$，可能再回表 | $O(1)$ |
| B+ 树范围查询 | $O(h\log m+r)$ 或 $O(hm+r)$ | $O(h+\lceil r/b\rceil)$，回表另计 | 流式 $O(1)$，收集结果 $O(r)$ |

!!! note "竞赛题简化口径"
    若题目没有强调磁盘页或阶 $m$ 的变化，常把 $m$ 当常数，于是 B 树和 B+ 树的单点查找、插入、删除都可写成 $O(\log n)$。若题目强调页大小、阶、关键字移动次数或外存访问次数，就应写出 $h$、$m$、$r$、$b$ 这些参数。
