# 正则表达式基础

## 文本模式与匹配范围

正则表达式（Regular Expression，regex）描述一组文本模式，用于搜索、提取、替换或格式检查。规则的含义同时取决于正则引擎、匹配 API 和选项；只有模式字符串相同，不能保证不同工具给出相同结果。

最简单的正则表达式就是普通字符串：

```text
error
```

它可以匹配文本中的 `error`。如果想匹配一个或多个数字，可以写成：

```regex
\d+
```

在支持这一简写的引擎中，它可以匹配 `1`、`404`、`2026` 等连续数字。GNU `grep -E` 使用的 ERE 不把 `\d` 作为可移植的数字简写；跨工具示例可显式写 `[0-9]+`。

正则表达式适合处理“文本中有什么结构”这类问题，例如找出日志里的状态码、提取文件名中的日期、把多余空白替换成一个空格。它不适合解析层级很复杂、语法很严格的完整语言，例如完整 HTML、JSON 或程序源码。

## 常见使用场景

| 场景 | 示例 |
| --- | --- |
| 搜索 | 在日志中查找包含 `timeout` 的行 |
| 校验 | 判断用户输入是否像邮箱、手机号或日期 |
| 提取 | 从 `2026-06-23.log` 中提取日期 |
| 替换 | 把多个连续空白替换成一个空格 |
| 切分 | 按逗号、分号或空白分割文本 |

## 基本元素

### 字面量

普通字符默认匹配自身：

```regex
cat
```

它会匹配 `cat`，也会匹配 `category` 里的前 3 个字符。

如果要匹配正则表达式里的特殊字符，需要用反斜杠转义。例如匹配真正的点号：

```regex
\.
```

常见需要转义的字符包括：

```text
. ^ $ * + ? { } [ ] \ | ( )
```

### 任意字符 `.`

点号 `.` 通常表示“任意单个字符”：

```regex
a.c
```

它可以匹配 `abc`、`a-c`、`a c`。

多数正则引擎里，`.` 默认不匹配换行符。是否能匹配换行，取决于具体工具和是否开启了类似 `DOTALL` 的选项。

### 字符类

字符类用 `[]` 表示“这里允许出现这些字符之一”：

```regex
[abc]
```

它可以匹配 `a`、`b` 或 `c` 中的任意一个。

常见写法如下：

| 写法 | 含义 |
| --- | --- |
| `[0-9]` | 任意一个数字 |
| `[a-z]` | 任意一个小写英文字母 |
| `[A-Za-z]` | 任意一个英文字母 |
| `[^0-9]` | 任意一个非数字字符 |

正则还提供了一些常用简写：

| 简写 | 近似含义 |
| --- | --- |
| `\d` | 数字字符；Python 的 Unicode 字符串模式还包含非 ASCII 十进制数字 |
| `\D` | 非数字 |
| `\w` | 单词字符，通常包括字母、数字和下划线 |
| `\W` | 非单词字符 |
| `\s` | 空白字符，例如空格、制表符、换行 |
| `\S` | 非空白字符 |

例如 Python 中 `re.fullmatch(r"\d+", "１２３")` 能匹配全角数字；`[0-9]+` 则只接受 ASCII 数字。`\w` 也不等于“英文单词”，`\b` 由单词字符与非单词字符的交界定义，并不执行中文分词。协议字段、文件名与用户文字应分别选择允许的字符范围。

### 重复次数

量词用来描述前一个元素重复多少次：

| 写法 | 含义 |
| --- | --- |
| `*` | 重复 0 次或多次 |
| `+` | 重复 1 次或多次 |
| `?` | 重复 0 次或 1 次 |
| `{m}` | 正好重复 `m` 次 |
| `{m,}` | 至少重复 `m` 次 |
| `{m,n}` | 重复 `m` 到 `n` 次 |

例如：

```regex
\d{4}-\d{2}-\d{2}
```

它可以匹配形如 `2026-06-23` 的日期文本；量词约束字符个数，不校验月份或日期是否存在。

### 位置匹配

有些符号只约束匹配位置，不消费字符：

| 写法 | 含义 |
| --- | --- |
| `^` | 字符串开头，或多行模式下的行首 |
| `$` | 结尾位置；一些引擎也允许匹配末尾换行符之前，多行模式下可匹配行尾 |
| `\b` | 单词边界 |

例如：

```regex
^ERROR
```

它表示只匹配以 `ERROR` 开头的文本。

```regex
\berror\b
```

它会匹配独立单词 `error`，通常不会匹配 `terror` 或 `errors` 中的一部分。格式校验应优先使用引擎的完整匹配 API，例如 Python `re.fullmatch`；不能在所有引擎中把 `^...$` 当成严格消费整个字符串的等价写法。

### 分组与选择

小括号 `()` 可以把一段模式组合起来：

```regex
(ha)+
```

它可以匹配 `ha`、`haha`、`hahaha`。

竖线 `|` 表示“或者”：

```regex
cat|dog
```

它可以匹配 `cat` 或 `dog`。

如果只想让选择发生在局部范围内，可以配合分组：

```regex
gr(a|e)y
```

它可以匹配 `gray` 或 `grey`。

## 捕获、提取与替换

分组默认会捕获匹配到的内容，便于后续提取。

例如从日期中提取年月日：

```regex
(\d{4})-(\d{2})-(\d{2})
```

匹配 `2026-06-23` 时：

| 分组 | 内容 |
| --- | --- |
| 整体匹配 | `2026-06-23` |
| 第 1 组 | `2026` |
| 第 2 组 | `06` |
| 第 3 组 | `23` |

如果只需要分组控制优先级，不需要捕获，可以使用非捕获分组：

```regex
(?:jpg|jpeg|png|gif)
```

替换字符串还有自己的一套语法，与正则模式分开解释。例如 Python 可把日期改写为斜杠形式：

```python
import re

result = re.sub(r"([0-9]{4})-([0-9]{2})-([0-9]{2})",
                r"\g<1>/\g<2>/\g<3>", "2026-06-23")
print(result)  # 2026/06/23
```

有的工具用 `\1`、`\2` 表示捕获组，有的语言或编辑器会使用 `$1`、`${1}`。写替换规则时要看当前工具的说明。

## 贪婪与非贪婪

量词默认通常是贪婪的，会尽可能多地匹配。

给定文本：

```html
<b>one</b><b>two</b>
```

规则：

```regex
<b>.*</b>
```

在常见回溯引擎中，这里会从第一个 `<b>` 匹配到最后一个 `</b>`：

```text
<b>one</b><b>two</b>
```

如果想尽量少匹配，可以使用非贪婪量词：

```regex
<b>.*?</b>
```

它会先匹配：

```text
<b>one</b>
```

非贪婪量词先尝试较少字符，仍会为满足后续模式继续扩展。若数据约定内容不能包含 `<`，可写 `[^<]*` 来表达这个约束；非贪婪不提供嵌套结构解析能力，也不保证没有性能风险。

## 在命令行中使用

### grep

`grep` 默认使用基础正则。常用 `-E` 开启扩展正则，让 `+`、`?`、`|`、`()` 等写法更自然：

```bash
grep -E 'ERROR|WARN' app.log
```

查找包含日期的行：

```bash
grep -E '[0-9]{4}-[0-9]{2}-[0-9]{2}' app.log
```

### ripgrep

`rg` 默认就支持常用正则语法，搜索源码和笔记时很方便：

```bash
rg '\bTODO\b' docs/
```

若搜索的是字面字符串，`rg -F` 可避免把用户输入解释为正则。默认引擎不支持反向引用和环视；需要这些功能且构建支持 PCRE2 时，可显式使用 `rg -P`，同时重新评估性能特性。

只查找 Markdown 文件中的二级标题：

```bash
rg '^## ' docs/ -g '*.md'
```

### sed

`sed -E` 常用于批量替换：

```bash
sed -E 's/[[:space:]]+/ /g' input.txt
```

`sed` 默认逐行处理，此命令把每行中的连续空白替换为一个空格，通常不会合并跨行的换行符。对比 Python 的 `re.sub(r"\s+", " ", text)`，后者可把字符串中的换行一起替换。

命令行中建议优先用单引号包住正则，减少 shell 对反斜杠、美元符号和感叹号等字符的额外解释。确实需要变量展开时，再改用双引号并仔细处理转义。

## 在 Python 中使用

Python 使用标准库 `re`。原始字符串 `r"..."` 只减少 Python 字符串字面量这一层的转义，正则引擎仍会解释反斜杠。

| API | 匹配范围与结果 |
| --- | --- |
| `re.search` | 在任意位置查找第一个匹配 |
| `re.match` | 只从字符串开头尝试，不要求消费全文 |
| `re.fullmatch` | 要求整个字符串匹配，适合格式校验 |
| `re.finditer` | 迭代不重叠匹配，保留分组和位置 |
| `re.findall` | 返回值形状受捕获组数量影响 |

动态拼入需按字面量处理的文本时使用 `re.escape`；它用于模式，不是通用的替换字符串转义函数。

```python title="regex_demo.py"
import re

text = "status=404 path=/login"

match = re.search(r"status=(\d+)", text)
if match:
    print(match.group(1))  # 404
```

查找所有日期：

```python
import re

text = "created=2026-06-23 updated=2026-06-24"
dates = re.findall(r"\d{4}-\d{2}-\d{2}", text)
print(dates)
```

替换连续空白：

```python
import re

text = "hello     regex\tworld"
clean = re.sub(r"\s+", " ", text)
print(clean)
```

## 常见模式

### 日期

匹配形如 `YYYY-MM-DD` 的日期：

```regex
\b\d{4}-\d{2}-\d{2}\b
```

这只能说明文本形状像日期，不能保证 `2026-99-99` 这种值一定有效。

### IPv4 地址

粗略匹配 IPv4 地址：

```regex
\b(?:\d{1,3}\.){3}\d{1,3}\b
```

这个规则可以匹配 `192.168.1.1`，也可能匹配 `999.999.999.999`。

若需要确认它是合法地址，直接交给 `ipaddress.IPv4Address`：

```python
from datetime import date
from ipaddress import IPv4Address

print(date.fromisoformat("2026-06-23"))
print(IPv4Address("192.0.2.10"))
```

日期解析器检查日历约束，IP 解析器检查地址语义，非法输入会抛出相应异常。若接口严格要求 `YYYY-MM-DD`，先用 `[0-9]{4}-[0-9]{2}-[0-9]{2}` 做完整匹配，再调用日期解析器，因为解析器可能接受其他合法 ISO 8601 形式。

### 文件扩展名

匹配常见图片文件名：

```regex
^.+\.(?:jpg|jpeg|png|gif|webp)$
```

如果需要忽略大小写，应使用对应工具的忽略大小写选项，例如 `grep -i`、`rg -i` 或 Python 的 `re.IGNORECASE`。

### Markdown 标题

匹配一级到四级 Markdown 标题，并捕获标题内容：

```regex
^(#{1,4})[ \t]+(.+)$
```

其中：

| 分组 | 含义 |
| --- | --- |
| 第 1 组 | 标题级别，例如 `##` |
| 第 2 组 | 标题文字 |

这只适合搜索约定格式的标题行；它会命中代码块中的示例，也没有覆盖 CommonMark 标题的全部规则。需要重建文档结构时应使用 Markdown 解析器。

## 方言与复杂度

JavaScript、Python、grep、sed、Nginx、数据库和编辑器里的正则语法并不完全一致。遇到查找、替换结果和预期不一致时，先确认当前工具使用的是哪一种正则引擎。

- `*` 可以匹配 0 次，所以 `a*` 能匹配空字符串。
- `.`、`+`、`?`、`|` 等字符有特殊含义，匹配字面量时要转义。
- `^` 和 `$` 的含义会受多行模式影响。
- 正则表达式通常只适合做格式初筛，不能替代完整解析器和业务校验。
- 嵌套重复的复杂模式可能导致性能问题，处理不可信输入时要格外谨慎。

### 自动机与回溯

理论上的正则表达式描述正则语言，可用有限自动机识别。工程引擎增加的反向引用等能力超出了经典正则语言的范围，运行方式和复杂度也会变化。

`^(a+)+$` 在某些回溯引擎中处理“许多 `a` 后接一个不匹配字符”时，需要探索大量重复划分，可能产生灾难性回溯。改成 `^a+$` 消除了多余嵌套。单纯把贪婪量词换为非贪婪，通常没有消除这些候选划分。

Rust regex/RE2 一类引擎限制语法以避免无界回溯；Python 标准库 `re` 支持更丰富的回溯行为，但没有通用的每次匹配超时参数。处理外部输入时，应限制输入长度、避免重叠的嵌套量词，或选择有时间界限的执行环境。Python 3.11 起支持原子分组与占有量词，它们会改变回溯机会，也可能改变匹配结果，需先证明语义仍符合要求。

### 用正例和反例界定规则

一条格式校验规则至少应检查正常输入、最短边界、空串、非法字符、额外前后缀、换行和超长输入。测试所要验证的是数据约束，不能只复述模式本身。

!!! question "例题：ASCII 状态码的完整匹配"
    接口字段要求恰好三个 ASCII 数字。`re.match(r"\d{3}", text)` 是否满足要求？至少给出两个反例，并写出更准确的判断。

    ??? success "参考答案"
        `"404extra"` 可因前缀匹配而通过，`"４０４"` 可因 Unicode 数字定义而通过。可使用 `re.fullmatch(r"[0-9]{3}", text) is not None`。若还要求属于已定义的 HTTP 状态码集合，需要继续做取值或业务语义校验。
