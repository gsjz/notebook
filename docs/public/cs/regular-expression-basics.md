# 正则表达式基础

## 简介

正则表达式，英文是 Regular Expression，常简称为 regex 或 regexp。它是一种描述文本模式的规则，常用于搜索、校验、提取和替换文本。

最简单的正则表达式就是普通字符串：

```text
error
```

它可以匹配文本中的 `error`。如果想匹配一个或多个数字，可以写成：

```regex
\d+
```

这条规则可以匹配 `1`、`404`、`2026` 这类连续数字。

!!! note "正则表达式描述的是文本模式"
    正则表达式适合处理“文本中有什么结构”这类问题，例如找出日志里的状态码、提取文件名中的日期、把多余空白替换成一个空格。它不适合解析层级很复杂、语法很严格的完整语言，例如完整 HTML、JSON 或程序源码。

## 常见使用场景

| 场景 | 示例 |
| --- | --- |
| 搜索 | 在日志中查找包含 `timeout` 的行 |
| 校验 | 判断用户输入是否像邮箱、手机号或日期 |
| 提取 | 从 `2026-06-23.log` 中提取日期 |
| 替换 | 把多个连续空白替换成一个空格 |
| 切分 | 按逗号、分号或空白分割文本 |

## 基本元素

### 字面量

普通字符默认匹配自身：

```regex
cat
```

它会匹配 `cat`，也会匹配 `category` 里的前 3 个字符。

如果要匹配正则表达式里的特殊字符，需要用反斜杠转义。例如匹配真正的点号：

```regex
\.
```

常见需要转义的字符包括：

```text
. ^ $ * + ? { } [ ] \ | ( )
```

### 任意字符 `.`

点号 `.` 通常表示“任意单个字符”：

```regex
a.c
```

它可以匹配 `abc`、`a-c`、`a c`。

!!! warning "点号通常不匹配换行"
    多数正则引擎里，`.` 默认不匹配换行符。是否能匹配换行，取决于具体工具和是否开启了类似 `DOTALL` 的选项。

### 字符类

字符类用 `[]` 表示“这里允许出现这些字符之一”：

```regex
[abc]
```

它可以匹配 `a`、`b` 或 `c` 中的任意一个。

常见写法如下：

| 写法 | 含义 |
| --- | --- |
| `[0-9]` | 任意一个数字 |
| `[a-z]` | 任意一个小写英文字母 |
| `[A-Za-z]` | 任意一个英文字母 |
| `[^0-9]` | 任意一个非数字字符 |

正则还提供了一些常用简写：

| 简写 | 近似含义 |
| --- | --- |
| `\d` | 数字，常见等价于 `[0-9]` |
| `\D` | 非数字 |
| `\w` | 单词字符，通常包括字母、数字和下划线 |
| `\W` | 非单词字符 |
| `\s` | 空白字符，例如空格、制表符、换行 |
| `\S` | 非空白字符 |

!!! note "简写的精确定义可能受引擎影响"
    `\d`、`\w`、`\s` 在不同语言、不同 Unicode 设置下可能略有差异。写脚本时可以接受这种便利；写安全校验或跨工具规则时，要确认当前正则引擎的定义。

### 重复次数

量词用来描述前一个元素重复多少次：

| 写法 | 含义 |
| --- | --- |
| `*` | 重复 0 次或多次 |
| `+` | 重复 1 次或多次 |
| `?` | 重复 0 次或 1 次 |
| `{m}` | 正好重复 `m` 次 |
| `{m,}` | 至少重复 `m` 次 |
| `{m,n}` | 重复 `m` 到 `n` 次 |

例如：

```regex
\d{4}-\d{2}-\d{2}
```

它可以匹配形如 `2026-06-23` 的日期文本。

### 位置匹配

有些符号不匹配具体字符，而是匹配位置：

| 写法 | 含义 |
| --- | --- |
| `^` | 字符串开头，或多行模式下的行首 |
| `$` | 字符串结尾，或多行模式下的行尾 |
| `\b` | 单词边界 |

例如：

```regex
^ERROR
```

它表示只匹配以 `ERROR` 开头的文本。

```regex
\berror\b
```

它会匹配独立单词 `error`，通常不会匹配 `terror` 或 `errors` 中的一部分。

### 分组与选择

小括号 `()` 可以把一段模式组合起来：

```regex
(ha)+
```

它可以匹配 `ha`、`haha`、`hahaha`。

竖线 `|` 表示“或者”：

```regex
cat|dog
```

它可以匹配 `cat` 或 `dog`。

如果只想让选择发生在局部范围内，可以配合分组：

```regex
gr(a|e)y
```

它可以匹配 `gray` 或 `grey`。

## 捕获、提取与替换

分组默认会捕获匹配到的内容，便于后续提取。

例如从日期中提取年月日：

```regex
(\d{4})-(\d{2})-(\d{2})
```

匹配 `2026-06-23` 时：

| 分组 | 内容 |
| --- | --- |
| 整体匹配 | `2026-06-23` |
| 第 1 组 | `2026` |
| 第 2 组 | `06` |
| 第 3 组 | `23` |

如果只需要分组控制优先级，不需要捕获，可以使用非捕获分组：

```regex
(?:jpg|jpeg|png|gif)
```

许多工具也支持在替换时引用捕获组。例如把 `2026-06-23` 改成 `2026/06/23`，思路是：

```text
查找：(\d{4})-(\d{2})-(\d{2})
替换：\1/\2/\3
```

!!! warning "替换引用写法不完全统一"
    有的工具用 `\1`、`\2` 表示捕获组，有的语言或编辑器会使用 `$1`、`${1}`。写替换规则时要看当前工具的说明。

## 贪婪与非贪婪

量词默认通常是贪婪的，会尽可能多地匹配。

给定文本：

```html
<b>one</b><b>two</b>
```

规则：

```regex
<b>.*</b>
```

可能会从第一个 `<b>` 一直匹配到最后一个 `</b>`：

```text
<b>one</b><b>two</b>
```

如果想尽量少匹配，可以使用非贪婪量词：

```regex
<b>.*?</b>
```

它会先匹配：

```text
<b>one</b>
```

!!! tip "先收窄范围，再考虑非贪婪"
    能用更明确的字符类时，通常比直接写 `.*?` 更稳。例如匹配一对简单标签中的内容，可以考虑 `[^<]*` 这类更受约束的规则。

## 在命令行中使用

### grep

`grep` 默认使用基础正则。常用 `-E` 开启扩展正则，让 `+`、`?`、`|`、`()` 等写法更自然：

```bash
grep -E 'ERROR|WARN' app.log
```

查找包含日期的行：

```bash
grep -E '[0-9]{4}-[0-9]{2}-[0-9]{2}' app.log
```

### ripgrep

`rg` 默认就支持常用正则语法，搜索源码和笔记时很方便：

```bash
rg '\bTODO\b' docs/
```

只查找 Markdown 文件中的二级标题：

```bash
rg '^## ' docs/ -g '*.md'
```

### sed

`sed -E` 常用于批量替换：

```bash
sed -E 's/[[:space:]]+/ /g' input.txt
```

这条命令把连续空白替换成一个空格。

!!! warning "shell 里要注意引号"
    命令行中建议优先用单引号包住正则，减少 shell 对反斜杠、美元符号和感叹号等字符的额外解释。确实需要变量展开时，再改用双引号并仔细处理转义。

## 在 Python 中使用

Python 使用标准库 `re` 处理正则表达式。写正则字符串时，通常使用原始字符串 `r"..."`，减少反斜杠转义带来的干扰。

```python title="regex_demo.py"
import re

text = "status=404 path=/login"

match = re.search(r"status=(\d+)", text)
if match:
    print(match.group(1))  # 404
```

查找所有日期：

```python
import re

text = "created=2026-06-23 updated=2026-06-24"
dates = re.findall(r"\d{4}-\d{2}-\d{2}", text)
print(dates)
```

替换连续空白：

```python
import re

text = "hello     regex\tworld"
clean = re.sub(r"\s+", " ", text)
print(clean)
```

## 常见模式

### 日期

匹配形如 `YYYY-MM-DD` 的日期：

```regex
\b\d{4}-\d{2}-\d{2}\b
```

这只能说明文本形状像日期，不能保证 `2026-99-99` 这种值一定有效。

### IPv4 地址

粗略匹配 IPv4 地址：

```regex
\b(?:\d{1,3}\.){3}\d{1,3}\b
```

这个规则可以匹配 `192.168.1.1`，也可能匹配 `999.999.999.999`。

如果需要严格校验每段在 `0` 到 `255` 之间，规则会明显变复杂，通常更建议交给专门的 IP 地址解析库。

### 文件扩展名

匹配常见图片文件名：

```regex
^.+\.(?:jpg|jpeg|png|gif|webp)$
```

如果需要忽略大小写，应使用对应工具的忽略大小写选项，例如 `grep -i`、`rg -i` 或 Python 的 `re.IGNORECASE`。

### Markdown 标题

匹配一级到四级 Markdown 标题，并捕获标题内容：

```regex
^(#{1,4})\s+(.+)$
```

其中：

| 分组 | 含义 |
| --- | --- |
| 第 1 组 | 标题级别，例如 `##` |
| 第 2 组 | 标题文字 |

## 常见易错点

!!! warning "注意正则方言差异"
    JavaScript、Python、grep、sed、Nginx、数据库和编辑器里的正则语法并不完全一致。遇到查找、替换结果和预期不一致时，先确认当前工具使用的是哪一种正则引擎。

- `*` 可以匹配 0 次，所以 `a*` 能匹配空字符串。
- `.`、`+`、`?`、`|` 等字符有特殊含义，匹配字面量时要转义。
- `^` 和 `$` 的含义会受多行模式影响。
- 正则表达式通常只适合做格式初筛，不能替代完整解析器和业务校验。
- 嵌套重复的复杂模式可能导致性能问题，处理不可信输入时要格外谨慎。

## 阅读正则的顺序

读一条正则时，可以按下面的顺序拆解：

1.  先找锚点，例如 `^`、`$`、`\b`，确认它限制的是整段文本、行，还是单词边界。
2.  再看字符范围，例如字面量、字符类、`\d`、`\w`、`\s`。
3.  接着看量词，例如 `+`、`*`、`?`、`{m,n}`。
4.  最后看分组、选择和捕获，确认哪些部分会被提取或替换引用。

!!! success "核心思路"
    正则表达式的关键是把“要找的文本”拆成字符范围、重复次数、位置约束和分组关系。先写能匹配正确样例的简单规则，再用反例逐步收紧，通常比一开始追求复杂通用规则更可靠。
