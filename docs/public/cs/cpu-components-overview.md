# CPU 内部主要元件

CPU 执行指令时，需要保存执行状态、计算数据和地址，并协调这些状态何时更新。组成原理常把 CPU 分为运算器、控制器、寄存器和内部总线；从实现角度，也可分成**数据通路**与**控制逻辑**。这两种划分交叉使用，不能把寄存器视为与运算器、控制器完全互斥的一类部件。

本文先使用单处理器的教学数据通路说明部件职责，再讨论流水线、寄存器重命名和精确异常的实现边界。

## 部件与状态

| 缩写 | 名称 | 保存或处理的对象 |
| --- | --- | --- |
| ALU | Arithmetic Logic Unit，算术逻辑单元 | 加减、逻辑、比较等运算 |
| ACC | Accumulator，累加器 | 累加器型指令的隐含操作数和结果 |
| GPR | General Purpose Register，通用寄存器 | 数据、中间结果或地址 |
| PC | Program Counter，程序计数器 | 指令地址；确切含义与观察阶段、ISA 有关 |
| IR | Instruction Register，指令寄存器 | 教学模型中当前指令的编码 |
| PSW | Program Status Word，程序状态字 | 条件码及可能的处理器控制状态 |
| MAR | Memory Address Register，存储器地址寄存器 | 当前访存地址 |
| MDR | Memory Data Register，存储器数据寄存器 | 从存储器读出或准备写入的数据 |

ALU 是组合逻辑，给定输入和功能选择后产生输出；寄存器是状态元件，在规定时刻锁存值。控制器给出选择信号和写使能，确保正确的结果在正确的边沿写入正确的寄存器。组合逻辑延迟、建立时间和时钟偏差共同约束可用时钟周期。

## 运算器与条件码

### ALU 与加法器

抽象 ALU 接收操作数 $A$、$B$ 和功能选择信号，产生结果 $F$ 及状态信息。加法器可通过取反和进位输入复用为减法器：

$$
A-B\equiv A+\overline B+1\pmod{2^n}
$$

这里的 $n$ 是运算位宽。等式必须按固定位宽理解；截断后结果与无限精度数学整数可能不同。比较可以利用减法产生的标志；地址生成也需要加法。现代处理器往往另设地址生成单元、移位器、乘除单元和向量执行单元，并非所有运算都挤在一个 ALU 中完成。

累加器结构把一个操作数位置隐含在指令中。例如：

$$
ACC\leftarrow ACC+M[X]
$$

可以缩短指令的地址字段，但限制了操作数组织。通用寄存器结构允许更灵活地安排操作数；不能要求每台处理器都有一个独立、必用的 `ACC`。

### 标志位的位级含义

| 标志 | 判断内容 | 典型用途 |
| --- | --- | --- |
| `CF` | 无符号进位；减法中的借位定义由 ISA 决定 | 多字加减、无符号比较 |
| `OF` | 有符号结果是否超出补码表示范围 | 有符号比较及溢出判断 |
| `ZF` | 截断后结果是否为零 | 相等判断 |
| `SF` | 截断后结果最高位 | 配合 `OF` 判断有符号大小 |

在 $n$ 位补码加法器中，设 $C_{n-1}$ 为进入符号位的进位，$C_n$ 为符号位产生的进位，则：

$$
OF=C_n\oplus C_{n-1}
$$

同号相加而结果异号，是等价的溢出判据。减法还需区分“加法器的进位输出”和“ISA 定义的借位标志”：例如用补码加法完成减法时，x86 的借位 `CF` 与最高位进位的关系不同于直接做无符号加法。

!!! question "例题：8 位加法的标志"
    对以下两次独立的 $8$ 位加法，分别给出结果、`CF`、`OF`、`ZF`、`SF`。约定 `CF` 取最高位进位，`SF` 取结果最高位。

    1. $\mathtt{7F_H}+\mathtt{01_H}$。
    2. $\mathtt{FF_H}+\mathtt{01_H}$。

    ??? success "参考答案"
        第一组结果为 $\mathtt{80_H}$，$CF=0$、$OF=1$、$ZF=0$、$SF=1$。无符号结果 $128$ 可表示；有符号的 $127+1$ 越界。

        第二组结果为 $\mathtt{00_H}$，$CF=1$、$OF=0$、$ZF=1$、$SF=0$。无符号的 $255+1$ 越界；有符号的 $-1+1=0$ 未越界。

`PSW` 在不同机器中可能还包含特权级、中断屏蔽等控制状态，不能把它永远等同于四个算术标志。部分 ISA 不采用集中式算术条件码，分支指令直接比较操作数。

## 控制器与指令执行

控制器结合指令译码、当前时序、状态标志和外部响应，产生寄存器写使能、数据源选择、ALU 功能以及存储器请求等控制信号。硬布线控制器用逻辑电路产生控制；微程序控制器以微指令组织控制序列。同一个现代处理器也可能结合多种机制。

### 取指和执行的数据流

设机器按字节编址、指令长度为 $L$ 字节，并且下列微操作按先后关系完成。一次抽象取指可写为：

$$
MAR\leftarrow PC,\qquad
MDR\leftarrow M[MAR],\qquad
IR\leftarrow MDR,\qquad
PC\leftarrow PC+L
$$

这组式子没有规定每步恰好一拍，也没有说明它们都能同拍完成。存储器响应可能需要等待；独立加法器可让 PC 更新与读请求重叠；单总线可能迫使一些传送分拍。

若随后执行 $ACC\leftarrow ACC+M[X]$，还需要把 $X$ 送到地址通路，读取操作数，经 ALU 加到 `ACC`，再按指令定义更新标志。取指读出的内容进入译码路径，数据读取进入操作数路径；比特序列本身不附带“指令”标签。现代系统还会用可执行权限、分离的指令/数据缓存等机制约束访问。

### PC 的阶段含义

在顺序教学模型中，取指后 PC 已更新，所以执行当前指令时它通常保存下一条顺序地址。分支、调用、返回和异常会改变后续控制流。

“PC 永远保存下一条执行指令地址”过于绝对：取指前后、架构可见状态、异常保存地址和推测取指指针可能不同。回答选择题应先识别题目采用的单指令模型；分析实际 ISA 时则遵循其分支基准和异常返回规则。

### 机器指令、微操作与控制信号

| 层次 | 例子 | 含义 |
| --- | --- | --- |
| 机器指令 | `add` | 软件请求的可见运算 |
| 微操作 | $R_1\leftarrow R_2+R_3$ | 数据通路上的状态变换 |
| 控制信号 | 寄存器读端口选择、ALU 加法选择、写使能 | 驱动实际电路完成变换 |

微操作不等同于微程序中的微指令，也不必等同于现代 x86 解码后的微操作计数；具体语境应保持一致。

## 寄存器宽度与访存接口

在单一并行存储器接口模型中，若有 $2^a$ 个可编址单元，每个单元为 $u$ 字节，则：

$$
C=2^a u\,\mathrm{B}
$$

MAR 至少需要 $a$ 位。MDR 则由该接口一次交换的数据位数决定，与 MAR 位数、机器字长均不必相同。可寻址容量也不等于已经安装的内存容量。

!!! question "例题：地址能力与数据宽度"
    某教学机器采用 $36$ 位字节地址，存储器接口每次交换 $64$ 位。MAR、MDR 各需多少位？最大可寻址容量是多少？若指令长度为 $4\,\mathrm{B}$，顺序 PC 增量是多少？

    ??? success "参考答案"
        MAR 为 $36$ 位，MDR 为 $64$ 位，可寻址 $2^{36}\,\mathrm{B}=64\,\mathrm{GiB}$，一次交换 $8\,\mathrm{B}$。PC 按指令长度增加 $4$，与一次访存能带回多少字节分别确定。

在实际处理器中，虚拟地址宽度、物理地址宽度、通用寄存器宽度、缓存行宽度和 DRAM 通道宽度可能全部不同。MAR/MDR 是有用的接口抽象，不能据此断言芯片中只有一对同名寄存器、每个加载都要越过外部引脚访问 DRAM。

## 内部连接与时间约束

CPU 内部总线连接寄存器、ALU 和暂存部件；系统总线连接处理器、主存和 I/O 等系统级部件。二者所处层次不同。多核芯片还可能使用环、网格等片内互连，内部连接也不必是一条共享导线。

单总线题需要同时检查**依赖关系**和**资源冲突**：某一拍可以有多个寄存器从总线上锁存，但只能有一个源驱动同一组总线。若 ALU 的两个操作数都来自同一总线，通常要先把一个操作数存入暂存寄存器。

!!! question "例题：单总线的加法微操作"
    某数据通路只有一条内部总线。ALU 的一端连接暂存寄存器 `Y`，另一端连接总线；结果只能在拍末锁存到 `Z`，`Z` 可在下一拍驱动总线。完成 $R_3\leftarrow R_1+R_2$ 至少需要几拍？

    ??? success "参考答案"
        在给定通路中至少需要 $3$ 拍：

        | 拍 | 传送与计算 |
        | --- | --- |
        | $1$ | $Y\leftarrow R_1$ |
        | $2$ | $Z\leftarrow Y+R_2$ |
        | $3$ | $R_3\leftarrow Z$ |

        两个源寄存器不能同拍共同驱动这条总线；`Z` 在拍末才得到新值，也不能提前用于本拍写回。若图中另有旁路或独立写回通路，最少拍数可能改变。

时钟周期是硬件的基本时间单位；指令延迟是某条指令从进入执行到结果可用或提交的时间；总线事务时间属于接口协议。平均每条指令的周期数 CPI 反映吞吐，不能直接当作每条指令的延迟。对执行 $N$ 条指令的程序：

$$
T_{\mathrm{CPU}}=N\times CPI\times T_{\mathrm{clk}}
$$

在能够每拍提交多条指令的处理器上，平均 CPI 可以小于 $1$，同时单条指令仍可能经过很多流水级。

## 乱序执行与精确异常

现代乱序处理器把体系结构寄存器映射到更多物理寄存器，以消除写后写、写后读等假相关。调度器可以先发射已经就绪的操作，但真正的读后写依赖仍须等待正确数据。

常见实现用重排序缓冲区（ROB）跟踪指令顺序。运算可以提前完成，提交按程序顺序推进；若发现异常，处理器可呈现一个精确边界：更早指令已完成，故障指令及更晚指令没有留下不应出现的体系结构效果。已经投机产生的缓存等微架构变化不一定随之消失，因此“未提交”不等于“从未产生任何硬件活动”。

!!! question "例题：乱序完成与异常提交"
    程序顺序为：指令 $I_1$ 加法、$I_2$ 加载、$I_3$ 无依赖乘法。乘法先算完，但 $I_2$ 随后报告缺页。在采用顺序提交、精确异常的模型中，异常处理程序可以看到 $I_3$ 的新寄存器结果吗？

    ??? success "参考答案"
        不可以。$I_3$ 可以完成执行，但不能越过尚未确定正常完成的 $I_2$ 提交。处理器保留 $I_1$ 的已提交状态，并按 ISA 保存故障位置；修复缺页后再恢复执行。执行完成、结果旁路和体系结构提交应分别判断。

[Boom 的 ROB 文档](https://github.com/riscv-boom/riscv-boom/blob/master/docs/sections/reorder-buffer.rst)给出了一个可阅读的开源乱序处理器实例；其具体组织不代表全部处理器。[Intel 软件开发手册](https://www.intel.com/content/www/us/en/developer/articles/technical/intel-sdm.html)可用于核对 x86 的程序状态与异常语义。数据通路计算还可结合[汇编语言基础](assembly-basics.md)和[总线](bus.md)。
