# CPU 内部主要元件

!!! abstract "本文要点"
    本文把 CPU 内部常考元件收拢到一篇里统一讲清：

    - 运算器到底包括什么，`ALU` 在里面处于什么位置。
    - 控制器如何完成取指、译码和控制信号生成。
    - `PC`、`IR`、`PSW`、通用寄存器、`MAR`、`MDR` 分别存什么。
    - CPU 内部总线和系统总线有什么区别。

## 英文缩写速查

### 处理器与功能部件

- `CPU` = `Central Processing Unit`，中央处理器
- `ALU` = `Arithmetic Logic Unit`，算术逻辑单元
- `ACC` = `Accumulator`，累加器

### 寄存器与寄存器组

- `PC` = `Program Counter`，程序计数器
- `IR` = `Instruction Register`，指令寄存器
- `PSW` = `Program Status Word`，程序状态字
- `MAR` = `Memory Address Register`，存储器地址寄存器
- `MDR` = `Memory Data Register`，存储器数据寄存器
- `GPRs` = `General Purpose Registers`，通用寄存器组

### 标志位

- `CF` = `Carry Flag`，进位/借位标志
- `ZF` = `Zero Flag`，零标志
- `OF` = `Overflow Flag`，溢出标志
- `SF` = `Sign Flag`，符号标志

### 文中记号补充

- `ALUop` = `ALU operation`，文中表示 `ALU` 的功能选择信号
- `OP` = `Operation`，文中公式里表示“执行某种运算”

!!! tip "一个速记方法"
    像 `PC`、`IR`、`MAR`、`MDR` 这类缩写，通常对应某类专用寄存器；像 `CF`、`ZF`、`OF`、`SF` 这类缩写，通常对应运算后得到的状态标志位。

## 为什么先看整体

初学 CPU 时，最容易遇到两个问题：

- 名词很多，但不知道谁负责“算”、谁负责“控”、谁负责“存地址”。
- 同样都是寄存器，`PC`、`IR`、`PSW`、`MAR`、`MDR`、通用寄存器的作用却完全不同。

因此，比起把元件拆成很多页，更有效的做法通常是先把整体框架搭起来，再顺着一条指令执行路径去理解各部件如何配合。

## 408 里常见的 CPU 内部划分

在组成原理的讲法里，CPU 常被拆成四块：

1. 运算器：负责加工数据。
2. 控制器：负责取指、译码、发出控制信号。
3. 寄存器：负责高速暂存指令、地址、数据和状态。
4. 内部总线：负责把 CPU 内部各部件连接起来。

如果换一种更现代的说法，也常会看到：

- 数据通路：偏“谁在搬数据、谁在算数据”。
- 控制单元：偏“谁在决定现在该干什么”。

这两种说法本质上仍然是在描述同一套硬件，只是强调角度不同。

!!! note "一个口径提醒"
    教材中的“运算器、控制器、寄存器组、内部总线”是一种很适合考试和入门分析的划分。现代处理器内部实现远比这复杂，但不影响你先用这套模型理解基础题。

## 先用一条指令把这些元件串起来

以“从主存取一条加法指令并执行”为例，可以先粗略理解为：

1. `PC` 给出下一条指令地址。
2. 地址送入 `MAR`，主存把指令读到 `MDR`。
3. 指令送入 `IR`，译码器识别这是一条什么指令。
4. 控制器结合时序信号，发出本条指令需要的微操作控制信号。
5. 操作数进入通用寄存器、`ACC` 或 ALU 输入端。
6. ALU 完成运算，结果写回寄存器。
7. `PSW` 更新标志位，供后续条件转移使用。

在这个过程中，内部总线一直在承担“把信息从一个部件送到另一个部件”的任务。

!!! tip "读这篇时建议始终盯住三条线"
    - 控制流：下一条指令地址由谁给出。
    - 数据流：操作数和结果在哪些部件之间流动。
    - 状态流：标志位何时产生，又被谁使用。

## 运算器

运算器可以理解为 CPU 内部的 **数据加工中心**。它负责把操作数接进来，完成算术或逻辑处理，再把结果送回寄存器或其他部件。

从教材常见口径看，运算器通常包含：

- 算术逻辑单元 `ALU`
- 移位相关部件
- 状态寄存器 `PSW`
- 若干用于暂存操作数和结果的寄存器

因此，运算器不是单独一块“只会加减乘除”的电路，而是一组围绕数据加工组织起来的部件集合。

### `ALU`：运算器的核心

`ALU` 是 **Arithmetic Logic Unit**，即算术逻辑单元。它位于 CPU 的数据通路中，负责执行最基本、最高频的运算任务，例如：

- 加、减
- 与、或、异或、取反
- 部分移位、比较和地址相关运算

从功能上看，可以先把一个 ALU 抽象成：

- 两个操作数输入 `A`、`B`
- 一个功能选择信号 `ALUop`
- 一个结果输出 `F`
- 若干状态标志输出，例如 `CF`、`OF`、`ZF`、`SF`

其中最关键的是 `ALUop`。它告诉 ALU：这一次要做加法、减法，还是逻辑运算。

### 为什么说 `ALU` 的核心是加法器

在硬件实现里，很多运算都可以尽量向“加法 + 变换”归约，因此 `ALU` 往往以加法器为核心。

原因主要有两个：

1. 加法是最基础、最常用的算术运算。
2. 减法、比较、地址计算、乘除法的迭代步骤，都常常能转写成“若干次加法/减法 + 移位”。

例如，减法并不一定单独做一套完全不同的电路，而是常通过补码规则转成加法：

$$
A-B=A+(-B)=A+\overline{B}+1
$$

这意味着一套加法器，配合取反电路、进位输入和选择逻辑，就能同时覆盖加法与减法。

!!! tip "硬件视角的核心想法"
    `ALU` 追求的不是“每种运算都各做一套独立电路”，而是“尽量复用一套基础电路，在控制信号驱动下完成多种操作”。

### `ACC`：累加器

在很多教学模型和早期结构里，会单独强调 **累加器 `ACC`**。它的典型角色是：

- 作为 ALU 的一个隐含操作数来源
- 作为运算结果的默认暂存位置

例如，一条累加器型指令常可理解为：

$$
(ACC)OP(A_1)\to ACC
$$

这样做的好处是能缩短指令格式，因为有一个操作数不必显式写在指令里。

!!! note "不要把 ACC 想得太现代"
    `ACC` 在组成原理题里很常见，因为它能清晰展示“一个操作数隐含在寄存器里”的思想；但很多现代通用寄存器架构并没有一个必须专门叫 `ACC` 的独占角色。

### `PSW`：程序状态字与标志寄存器

运算器不只产生“结果值”，还要产生“结果状态”。这就是 `PSW` 或标志寄存器存在的原因。

最常见的几类标志包括：

- `CF`：进位/借位标志
- `ZF`：零标志
- `OF`：溢出标志
- `SF`：符号标志

这些状态随后会被条件转移、比较、异常处理等逻辑使用。

最容易混的两组概念是：

- `CF` 与 `OF`
- `ZF` 与 `SF`

其中：

- `CF` 主要服务于无符号数运算
- `OF` 主要服务于有符号数运算
- `ZF=1` 表示结果恰好为 0
- `SF` 常反映结果最高位

### 一个紧凑例子：补码加法与状态位

下面用 8 位补码做一个最常见的例子：

$$
01111111 + 00000001 = 10000000
$$

如果把它们当作 **有符号数**：

- `01111111` 表示 `+127`
- `00000001` 表示 `+1`
- `10000000` 表示 `-128`

显然，`127+1` 的数学结果应为 `128`，但 8 位补码无法表示 `+128`，所以这里发生了 **有符号溢出**，即 `OF=1`。

这里也正好体现出：

- `CF` 回答“无符号意义下是否溢出”
- `OF` 回答“有符号意义下是否溢出”

## 控制器

控制器是 CPU 中负责 **协调和指挥** 的部分。它本身并不直接完成大量数据运算，但它决定：

- 什么时候取指
- 什么时候译码
- 哪个寄存器该送数
- `ALU` 该执行什么操作
- 结果该写回哪里

如果把 CPU 比作一个流水作业现场，那么运算器更像“加工设备”，控制器更像“调度系统”。

### 控制器通常包含什么

在教材口径里，控制器往往与这些部件紧密相关：

- `PC`：给出下一条指令地址
- `IR`：暂存当前指令
- 指令译码器：识别操作码
- 时序系统：给出节拍和时钟基准
- 控制逻辑：产生具体微操作控制信号

### `PC`：程序计数器

`PC` 是 **Program Counter**，其最核心的功能只有一句话：

**保存下一条将要执行的指令地址。**

很多选择题的错误都来自把它误记成：

- 当前正在执行的指令地址
- 某个操作数地址
- 某个数据地址

这些都不对。

程序顺序执行时，`PC` 会自动更新为下一条顺序指令的地址；程序发生分支、调用、返回、中断、异常时，`PC` 会被改写为新的目标地址。

因此，`PC` 实际上就是程序控制流的“入口指针”。

### `IR` 与指令译码器

`IR` 是 **Instruction Register**，即指令寄存器。它的作用是：

**暂存当前正在执行的指令。**

而指令译码器的核心任务是：

**分析 `IR` 中操作码字段的含义，识别当前指令的类型。**

因此：

- `PC` 解决“去哪里取”
- `IR` 解决“取回来的是谁”
- 译码器解决“这条指令到底要干什么”

### 时序系统与控制逻辑

CPU 不是“想做什么就立刻乱做”，而是必须按时序分步骤执行。

时序系统的作用，就是给整个执行过程提供统一的时间基准。例如：

- 当前处在取指阶段
- 当前处在译码阶段
- 当前处在执行阶段

控制逻辑则会结合：

- 译码结果
- 时序信号
- 当前状态标志

进一步发出真正能驱动数据通路的微操作控制信号。

!!! note "控制器的本质"
    控制器的本质，不只是“会取指”或“会译码”，而是在时序驱动下把一条机器指令翻译成一串能让各部件协同工作的控制信号。

### 从机器指令到微操作

教材里常说“一条指令由若干微操作组成”，这里的意思可以这样理解：

- 机器指令回答“程序想让 CPU 做什么”
- 微操作回答“CPU 在某个节拍上具体搬什么、算什么、写回什么”

例如，最基本的取指过程就可以拆成一串更细的动作：

1. `(PC) \to MAR`
2. 主存读：`M(MAR) \to MDR`
3. `(MDR) \to IR`
4. `PC \to PC+1` 或更新为下一条顺序地址

如果后面是一条加法指令，那么执行阶段还会继续分解成：

1. 取操作数
2. 把操作数送入 `ALU`
3. 结果写回目标寄存器
4. 更新 `PSW`

!!! note "先分清三层概念"
    - 机器指令：程序员视角的一条指令。
    - 微操作：某个时刻完成的一步基本硬件动作。
    - 控制信号：真正驱动寄存器送数、ALU 运算、主存读写的电信号。

### 指令周期与时钟周期

时钟周期是 CPU 最基本的时间节拍；指令周期则是执行完一条指令所经历的全部时间。

因此：

- 时钟周期回答“最小一步有多长”
- 指令周期回答“一条指令总共走了多少步”

在入门模型里，你可以先把它理解为：

- 一个指令周期通常包含若干个时钟周期
- 取指、译码、执行这些阶段，都要落到具体时钟节拍上展开

!!! warning "一个常见误区"
    不要把“指令周期”“时钟周期”“总线周期”混成同一个量。它们都和时间有关，但描述的是不同层面的节奏。

## 寄存器

寄存器是 CPU 内部速度最快的一组小型暂存单元。它们负责保存：

- 指令
- 地址
- 数据
- 状态

但不同寄存器的分工非常明确。

### 通用寄存器

通用寄存器 `GPRs` 可以理解为 CPU 内部速度最快的一组工作台，供程序临时存放：

- 操作数
- 中间结果
- 地址
- 指针

在 408 / 教材口径里，通用寄存器既可以存 **数据**，也可以存 **地址**。这也是一个经典选择题考点。

从基础模型看，通用寄存器的位数通常与 **机器字长** 相匹配，因为它们经常直接参与 CPU 的整数数据运算。

### `MAR`：存储器地址寄存器

`MAR` 是 **Memory Address Register**，即存储器地址寄存器。它保存的是：

**当前要访问的主存单元地址。**

无论是取指，还是读写数据，只要要访问主存，地址通常都要先进入 `MAR`，再送往存储器系统。

### `MDR`：存储器数据寄存器

`MDR` 是 **Memory Data Register**，即存储器数据寄存器。它保存的是：

- 刚从主存读出来的数据
- 或即将写回主存的数据

因此，`MDR` 可以理解为 CPU 和主存进行数据交换时的缓冲位置。

### `MAR` 和 `MDR` 的位数为什么常不同

这是 408 里很常见的一类选择题。

- `MAR` 的位数主要取决于 **可寻址空间大小**，也可理解为和地址线位数密切相关。
- `MDR` 的位数主要取决于 **一次并行交换的数据位数**，也就是和数据线位数密切相关。

例如，若一台机器按字节编址、可寻址空间为 $4\text{GB}$，那么地址空间大小为 $2^{32}$ 个字节，`MAR` 至少需要 32 位；若它的数据线宽度为 64 位，则 `MDR` 通常按 64 位理解更自然。

所以：

- `MAR` 更关心“最多要指出多少个位置”
- `MDR` 更关心“一次能并行带多少位数据”

!!! tip "做题时的抓手"
    看到 `MAR` 先想地址空间、编址方式、地址线；看到 `MDR` 先想存储字长、数据线宽度和一次传输的数据位数。

### 一次读主存与写主存

读主存时，可以先用下面这条数据流理解：

$$
地址 \to MAR \to 主存 \to MDR
$$

若这次是取指，那么后面通常还会继续：

$$
MDR \to IR
$$

若这次是写主存，则可粗略理解为：

$$
目标地址 \to MAR,\quad 待写数据 \to MDR \to 主存
$$

因此：

- `MAR` 解决“访问哪里”
- `MDR` 解决“交换什么数据”

### 主存里的二进制序列，为什么有时是指令，有时是数据

从冯·诺依曼结构的角度看，指令和数据都可以放在同一主存中。主存本身并不会主动标记“这块一定是指令”或“这块一定是数据”。

真正完成区分的是 CPU 当前所处的工作阶段和后续去向：

- 若当前处在取指阶段，读出的内容通常会送入 `IR`，于是它被当作指令解释。
- 若当前处在执行阶段，读出的内容可能送入通用寄存器或 `ALU` 输入端，于是它被当作数据使用。

也就是说，**同一段二进制内容在硬件眼里先只是比特序列，是否被当作指令或数据，要看控制器在当下如何组织这次访问。**

!!! note "这也是一个很好的总理解题"
    “指令和数据如何区分”本质上考的不是主存会不会分类，而是你是否理解 CPU 在不同时序下会把读出的内容送往不同部件。

### 哪些寄存器程序员可见，哪些不可见

从汇编学习和 408 的基础口径看：

- 通用寄存器、部分状态信息、`PC` 常被视为程序员可见或可间接控制
- `IR`、`MAR`、`MDR` 通常属于 CPU 的内部工作寄存器，对汇编语言程序员不可见

!!! warning "一个常见误区"
    `PC` 是专用寄存器，但它不等于“完全透明”；`IR`、`MAR`、`MDR` 才更接近典型的内部工作寄存器。

## CPU 内部总线

CPU 内部总线，也常称 **片内总线**，是芯片内部用于连接各寄存器、`ALU` 和其他 CPU 内部部件的数据传送通路。

它的核心作用是：

**让 CPU 内部各个功能部件之间能够交换信息。**

例如：

- `PC` 把地址送给 `MAR`
- `MDR` 把数据送给 `IR`
- 通用寄存器把操作数送给 `ALU`

这些过程都离不开内部连接通路。

### 它和系统总线不是一回事

这是最重要的边界之一：

- **内部总线**：CPU 芯片内部使用
- **系统总线**：连接 CPU、主存、I/O 接口等外部功能部件

所以：

- 内部总线更强调“片内部件怎么互连”
- 系统总线更强调“整台计算机各大模块怎么互连”

不要把“CPU 内部总线”和“地址总线、数据总线、控制总线”机械混成同一层概念；后者通常是按系统总线上传输信息类型来分。

## 两个紧凑例子

### 例 1：取指过程

取指过程常可粗略写成：

$$
PC \to MAR \to 主存 \to MDR \to IR
$$

这条链说明：

- `PC` 给出地址
- `MAR` 暂存地址
- 主存把内容送到 `MDR`
- `IR` 保存当前指令

后续译码与控制都围绕 `IR` 中的内容展开。

### 例 2：一条累加器型加法指令

若当前指令可理解为：

$$
(ACC)+(M[X])\to ACC
$$

则可粗略理解为：

1. `X` 地址相关信息进入 `MAR`
2. 主存把 `M[X]` 读到 `MDR`
3. `ACC` 和 `MDR` 中的数据送入 `ALU`
4. `ALU` 完成加法
5. 结果写回 `ACC`
6. `PSW` 更新相关标志位

这个例子正好把运算器、寄存器、控制器和内部总线都串起来了。

## 408 / 应试补充

### 常考结论 1：不同寄存器的“存什么”不要混

- `PC` 存下一条指令地址
- `IR` 存当前正在执行的指令
- `PSW` 存状态信息
- `MAR` 存主存地址
- `MDR` 存主存读出或待写入的数据

### 常考结论 2：`ALU` 的核心部件是加法器

逻辑运算、减法、比较，乃至部分乘除实现，都和它有关。

### 常考结论 3：`CF` 看无符号，`OF` 看有符号

- 无符号加减重点看 `CF`
- 有符号加减重点看 `OF`

一个常用判据是：

$$
OF=C_n\oplus C_{n-1}
$$

### 常考结论 4：数据通路不等于控制器

数据通路强调数据经过哪些部件，例如 `PC`、`ALU`、寄存器、状态寄存器等；控制器负责产生控制信号去驱动它们工作。选择题里经常故意把这两个概念混在一起。

### 常考结论 5：通用寄存器不等于专用寄存器

通用寄存器可以存数据和地址；但 `PC`、`IR`、`PSW`、`MAR`、`MDR` 各自承担明确的专门职责，不能混着记。

### 常考结论 6：内部总线不等于系统总线

内部总线用于 CPU 片内互连；系统总线连接 CPU、主存和 I/O。若题目不先分清这一层，后面几乎一定会做错。

### 常考结论 7：`MAR` 看地址能力，`MDR` 看数据交换宽度

- `MAR` 位数常和地址线位数对应
- `MDR` 位数常和数据线位数对应
- 二者不必相等

### 常考结论 8：一条机器指令不是“一拍完成的一个动作”

控制器通常会把一条机器指令拆成若干微操作，再按时序逐步执行。题目若问“取指后发生什么”“哪一步先送入 `IR`”，本质上就是在考这条执行链。

### 常考结论 9：主存不负责区分指令和数据

区分依赖 CPU 的当前阶段和控制信号组织：

- 送入 `IR` 时按指令解释
- 送入寄存器或 `ALU` 时按数据处理

### 常考结论 10：时钟周期、指令周期、总线周期不是同义词

- 时钟周期是最基本节拍
- 指令周期是执行一条指令的总时间
- 总线周期是完成一次总线事务的大致时间单位

??? note "易混点速记"
    - `PC` 管“下一条去哪取”。
    - `IR` 管“当前取回的是哪条指令”。
    - `MAR` 管“访问哪里”。
    - `MDR` 管“交换什么数据”。
    - `CF` 和 `OF` 不是一回事。
    - 数据通路和控制器不是一回事。
    - `MAR` 和 `MDR` 的位数未必相同。
    - 指令和数据不是靠主存“贴标签”区分的。

!!! success "一句话总结"
    学 CPU 元件时，最关键的不是背名词，而是始终追问三件事：它里面放的是什么、它什么时候更新、它和谁发生数据交换。
